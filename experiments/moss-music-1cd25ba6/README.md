# MOSS-Music, разовый прогон 1cd25ba6

Сравнение открытой модели [MOSS-Music](https://github.com/OpenMOSS/MOSS-Music) с Музыкальным анализатором АудиоЛада. Это не часть приложения: каталог, прод и зависимости Next.js не меняются. Аудио в git не кладётся.

MERGE=NO. DEPLOY=NO.

## Что запускать

Аудио лежит в одной папке с `tracks.json`. Имена файлов фиксированы:

| Файл | Метка голоса | Инструменты, если известны |
| --- | --- | --- |
| `tihaya-garmoniya.mp3` | instrumental | нет метки |
| `last-plastinka.wav` | instrumental | нет метки |
| `solnechnoe-utro-v-rime.mp3` | instrumental | piano, guitar |
| `kolybelnaya-vocal.mp3` | vocal | нет метки |
| `klyuch-k-izobiliyu.mp3` | speech | нет метки |

```bash
cd experiments/moss-music-1cd25ba6
# положить сюда пять файлов, не коммитить
./setup.sh
./run.sh
```

`./run.sh` без аргументов читает `tracks.json` и берёт аудио из той же папки. Модель загружается один раз и обслуживает все треки и все промпты. После прогона в `var/results/` лежат `results.json`, `results.md` и `comparison.md`.

Повторная сверка без нового прогона:

```bash
python3 compare.py --results var/results/results.json --out var/results/comparison.md
```

Другой каталог аудио: `./run.sh --input-dir /путь/к/папке`. Первые N файлов манифеста: `./run.sh --limit N`.

Вариант Instruct. Thinking не скачивается: это вторые 17 ГиБ и длинная генерация, на одну L4 их не ставим рядом.

Путь генерации — официальный Transformers из `src/` этого коммита (`infer.py` / `hf_inference.py`), не SGLang. Upstream рекомендует SGLang для качества; здесь нужен один процесс, жадный декодер и замер видеопамяти. `trust_remote_code` у загрузчика выключен: класс берётся из закреплённого `src/`, а короткая копия конфига внутри весов ломает `audio_config`.

Промпты на английском (`prompts.json`): карточка указывает en и zh. Ответы пишутся как есть. Таблица сравнения на русском. Сэмплирование выключено, seed 0, `max_new_tokens` ограничен.

## L4 24 ГБ

Это не блокер. Ориентир такой:

- L4 в `nvidia-smi` обычно показывает около 23034 MiB.
- Веса BF16 занимают около 16,9 ГиБ. После загрузки остаётся примерно 5 ГиБ.
- Кодировщик режет мел окнами около 4 с (`n_window=200`), а не одним вниманием на весь трек.
- Пять треков короче 5 минут. У LLM контекст 12,5 аудиотокенов в секунду, KV на такой трек — сотни мегабайт.
- `setup.sh` не начинает скачивание, если у `cuda:0` меньше 22000 MiB.
- `run.py` не читает веса, если CUDA видит меньше 22 ГиБ, и останавливается с частичным `results.json`, если во время генерации кончится видеопамять.

На этой машине карты нет, поэтому влезание в 24 ГБ посчитано по размеру весов и коду, а не измерено прогоном. fp32 и второй экземпляр модели на L4 не помещаются.

## Диск и время

Свободно нужно от 45 ГБ. Веса около 17 ГБ, venv с CUDA-колёсами около 6–8 ГБ. Диск VM 150 ГБ для этого достаточен.

Оценка на L4, не замер. Жадный декодер ограничен примерно 1024 новыми токенами на трек.

| Шаг | Время |
| --- | --- |
| `setup.sh` в первый раз, сеть до Hugging Face | 20–45 мин |
| Повторный `setup.sh`, если штамп SHA256 уже есть | около минуты |
| Загрузка модели в GPU | 1–3 мин |
| Пять треков, шесть промптов | 25–70 мин |
| Весь первый проход | около 50–110 мин, цель меньше 2 часов |

`run.sh` печатает секунды каждого промпта. Если первый промпт идёт дольше трёх минут, остальной прогон может выйти за два часа: это повод остановить VM, а не ждать все пять треков молча.

## Проверки без GPU

```bash
bash -n setup.sh run.sh
./setup.sh --plan
python3 -m py_compile manifest.py metrics.py compare.py engine.py run.py test_kit.py
python3 test_kit.py
python3 run.py --manifest tracks.json --input-dir /tmp --dry-run   # код 2: файлов нет
```

`--dry-run` проверяет SHA256 и пишет пустые ответы, модель не грузится. `--cpu-smoke` дополнительно читает длительность wav. Сам MOSS на CPU здесь не запускается: BF16 не входит в память этой среды.

## Что считается верным

Голос: `instrumental` — голоса нет, `vocal` — пение, `speech` — речь. `mixed` у анализатора — утверждение «голос есть», но не точный класс. Экран «не определено» — воздержание, в знаменатель входит и верным не считается.

Инструменты считаются только там, где метка задана. Сейчас это piano и guitar у «Солнечного утра в Риме». Ищем слово в ответе MOSS и в списке анализатора. Лишние инструменты не штрафуются. У трёх других треков списка анализатора в репозитории нет, это не ошибка анализатора.

Снимки двух уже разобранных треков: `analyzer/tihaya-garmoniya.json`, `analyzer/poslednyaya-plastinka.json`. Полный экспорт «Последней пластинки» в git не входит. Свой JSON можно передать полем `analyzer` в манифесте.
