## Метод и причины выбора

Сохраняется один потоковый проход ffmpeg, mono 8 kHz, ограничение один час и таймаут 120 секунд. На каждые 400 samples (50 мс) добавлен FFT 512 с окном Hann. Хранятся только последовательности RMS/flux и предыдущий спектр: память ограничена длительностью в пределах часа; 20 малых FFT/с и 26 лагов автокорреляции. Ни нейросети, ни HPSS/STFT всей записи, ни дополнительная зависимость не нужны.

Вместо LUFS-нормализации второго прохода используются только признаки, инвариантные к постоянному gain. При `x → g·x` RMS, спектральные амплитуды и положительные разности масштабируются на `|g|`, который сокращается в каждом отношении. Разности уровней RMS в dB также сохраняются. Нет абсолютного порога амплитуды для атак или активности; интегральный RMS используется только как относительный знаменатель/порог, без вклада абсолютного уровня. LUFS и пики сохраняются отдельными техническими полями.

- `onset_density`: локальные максимумы положительной разности RMS, порог `max(0.12·RMS_трека, 0.2·maxRise)`, число атак / длительность. Граница 4 атаки/с ограничивает вклад плотной перкуссии.
- `spectral_flux`: сумма положительных изменений амплитуд FFT / сумма амплитуд. Первая атака файла исключена. `A = clip((flux − 0.10) / 0.30)`: слабое движение спектра имеет малый вклад; насыщение при 0.40.
- `percussive_ratio`: `Σ max(0, magnitude_t − 2·magnitude_prev) / Σ magnitude_t`, грубый временной остаток резких спектральных атак. Это не выделенная дорожка ударных и не настоящий HPSS. Небольшой остаток до 0.03 игнорируется, насыщение при 0.30.
- `low_band_onset_ratio`: положительные изменения FFT до 250 Hz / полная спектральная амплитуда. Постоянный бас сам по себе баллов не даёт.
- `rhythm_salience`: максимальная нормированная автокорреляция центрированного flux по лагам 5–30 окон, то есть 40–240 импульсов/мин. Это поддержка регулярности, не выбранный BPM и не вероятность. Низкий темп с чёткой пульсацией остаётся возможным.
- Яркость: амплитудно-взвешенный спектральный центроид. Динамика: P95–P10 активных RMS окон, активность выше 1% RMS трека. Оба признака дают только небольшую добавку при наличии спектральной активности; яркий pad или большие паузы сами по себе не означают высокую энергию.

`clip(x) = min(1, max(0, x))`. Итог округляется до целого:

```text
E = 100 · [0.20·clip(onsets/4)
         + 0.30·A
         + 0.25·clip((perc−0.03)/0.27)
         + 0.10·A·clip(low/0.20)
         + 0.05·A·clip(pulse/0.70)
         + 0.05·A·clip(centroid/2000)
         + 0.05·A·clip(dynamics/12)]
```

Абсолютная громкость имеет вес **0**. Тишина даёт 0. Для отсутствующих измерений сохраняется unknown/null, а не RMS-прокси. Веса: 75% атаки/flux/перкуссия, 10% низкочастотные атаки, остальные 15% — поддержка. Начальный вариант слишком высоко оценивал lounge jazz из-за насыщения шкал слабого flux и плотности атак. Диапазоны расширены, плотность снова основана на RMS-атаках, а не мелких спектральных колебаниях, и больший вес дан резким транзиентам. Значения грубые и общие: нет условий по названию, жанру, файлу, LUFS или отдельному треку. Тестовые шесть записей использованы для sanity check и настройки начальной шкалы; независимой валидацией её считать нельзя.

## Проверка gain

Для каждого исходника выполнено два преобразования, на исходных каналах до анализа, без перекодирования в lossy:

```sh
~/.local/bin/ffmpeg -nostdin -y -v error -i INPUT -map 0:a:0 \
  -af 'volume=-6dB,alimiter=limit=0.95:level=false:attack=5:release=50:latency=true' \
  -c:a pcm_f32le /tmp/audiolad-eval-09d393ce/energy-v2/VARIANT.wav
```

Второй вариант: `volume=3dB`, остальные параметры те же. Limiter без makeup gain; он может менять форму атак, поэтому это более строгая проверка, чем чистое масштабирование. JSON сохраняет фильтр, score, Δ, LUFS и все дескрипторы каждого варианта. Для чистого масштабирования синтетики проверены gain 0.001, −6, 0 и +3 dB: разброс ≤3, перкуссионный сигнал выше sustained pad минимум на 20. Отдельно проверено, что изменение только поля LUFS не влияет на итог и что legacy energy не перекрывает новый DSP.

Для воспроизведения V1 можно извлечь `local-dsp.mjs` и `features.mjs` из исходной базы `64164db1` во временный каталог; далее вызвать `measureLocalAudio` для тех же SHA-256. Для V2 использовать текущий модуль с `PATH="$HOME/.local/bin:$PATH"`. Временный runner этой сессии: `/tmp/audiolad-eval-09d393ce/energy-v2/evaluate.mjs`; он проверяет gap и gain-deltas через assert.
