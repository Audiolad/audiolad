# Персональные подборки закрытого каталога (73b4869d)

Администратор в `/admin/business-catalog/collections` выбирает существующие допущенные альбомы/треки, создаёт подборку и копирует секретную ссылку. Владелец и приглашённый слушатель могут одновременно открыть её на телефоне и компьютере без регистрации. Каждое устройство получает собственную cookie; ссылка не привязана к одной сессии. Это общий механизм для любых заведений.

В БД хранится SHA-256 случайного секрета, исходная ссылка показывается только при создании или перевыпуске в поле с кнопкой копирования. Перевыпуск атомарно меняет хеш и снимает отзыв: старые ссылки/cookie сразу закрыты для новых запросов, новая ссылка работает. Отзыв закрывает и сохранённую витрину аккаунта. Подборка и назначения при этом сохраняются; перевыпуск может снова включить их.

Аудио и обложки проходят серверный proxy с актуальной проверкой токена, состава и допусков; Range сохранён. Storage URL, master links и кнопок скачивания нет. Закрытый каталог и другие подборки не перечисляются. Сохранены noindex и no-referrer, новые внешние ссылки не добавлены. Уже переданные байты отозвать нельзя; открытый плеер проверяет разрешение каждые 15 секунд.

Зелёная CTA «Подключить заведение – 7 дней в подарок» использует `business-app-btn business-app-btn-cta`, существующий `BusinessGuestStartCta` и guest-start с явным принятием действующей оферты. Простое открытие или play подарок не запускает. Дни и цена берутся из `BUSINESS_GIFT_DAYS`, `formatBusinessMonthlyPrice` и периода действующего плана. После старта открывается существующий кабинет: ИНН и адрес, затем оплата 799 ₽ за 30 дней по текущему тарифу. Новый checkout, скидки, юридические тексты и правила подарка не добавлены. При выключенном быстром старте сохранён существующий путь регистрации.

`rememberPersonalCollection` сохраняет выбор за проверенным Auth user id. Триггер в той же транзакции заполняет пустые назначения заведений владельца направления cafe. Новое заведение наследует последнюю активную подборку аккаунта; другое уже заданное назначение сохраняется. Привязка почты к anonymous account сохраняет user id. В кабинете остаётся «Ваша подборка».

`loadWorkspaceCatalog`, используемый страницей, `/api/business/workspace/queue`, проверками track-url/cover и привязанными устройствами, пересекает обычный допущенный пул с живыми треками назначенной подборки. Проверяются принадлежность заведения владельцу и связь аккаунта, публикация, business_only, паспорт, cafe sound и блокировки прав; существующие eligibility gates заведения продолжают действовать. Ни один новый трек не добавляется. При отзыве или пустом пересечении возвращается обычный допущенный каталог; ошибка чтения закрывает выдачу. Для заведений без подборки сохраняется обычный каталог. Движок зала, spa-player-engine, hall-loop-audio и hall-wake-lock не менялись.

## Миграция и выпуск

Подготовлены `supabase/migrations/20270402120000_business_personal_collections.sql` и `supabase/rollbacks/20270402120000_business_personal_collections.rollback.sql`. Timestamp уникален; файл `20270401120000_business_guest_default_venue_name.sql` и rollback из #1306 не изменялись.

В одной миграции: таблицы подборок, элементов, аккаунтов и `business_personal_collection_locations`; два триггера привязки/наследования; service-only каталожные RPC. Все новые таблицы с RLS, anon/authenticated не имеют прямого доступа. Миграция аддитивная, данные не удаляет. **Выпуск требует отдельного согласия Сергея, поскольку включает миграцию.** На реальные или общие БД она не применялась. Production, Docker, инфраструктура, зависимости и lockfile не затронуты. Коммит и деплой не выполнялись.

## Откат без удаления данных

Сначала вернуть прежний код, затем по отдельному согласованию выполнить подготовленный rollback. Отключаются только новые триггеры и доступ к новым объектам, данные сохраняются. Для повторного включения вернуть права из миграции и включить эти два триггера; не повторять CREATE TABLE поверх сохранённых таблиц.

```sql
-- Non-destructive rollback: disable feature access; retain collections and account links.
-- Roll back application code first. No DROP/DELETE, no changes to existing catalog/billing.
BEGIN;
ALTER TABLE public.business_personal_collection_accounts DISABLE TRIGGER business_personal_collection_account_attach;
ALTER TABLE public.business_locations DISABLE TRIGGER business_personal_collection_location_inherit;
REVOKE ALL ON FUNCTION public.business_personal_collection_location_tracks(uuid) FROM service_role;
REVOKE ALL ON public.business_personal_collection_locations FROM service_role;
REVOKE ALL ON FUNCTION public.business_personal_collection_tracks(uuid),
  public.create_business_personal_collection(text,text,uuid,uuid[]) FROM service_role;
REVOKE ALL ON public.business_personal_collections, public.business_personal_collection_items,
  public.business_personal_collection_accounts FROM service_role;
COMMIT;
```

2. Создать подборку из допущенных альбомов и отдельных треков. Открыть одну ссылку без сессий на телефоне и компьютере одновременно; проверить play/pause/next/seek, автопереходы, обложки, отсутствие URL хранилища и download UI.
3. Проверить отказ поддельного секрета, чужого трека/подборки и прямых PostgREST/RPC anon/authenticated. Простое открытие и play не должны создавать access grants.
4. Нажать зелёную CTA, принять оферту, проверить один текущий подарок, кабинет, ИНН/адрес и существующую оплату. Отдельно проверить регистрацию при выключенном guest-start, привязку почты и сохранение user id.
5. Проверить queue/track-url и плеер заведения: только пересечение назначенной подборки с существующим допуском. Убрать допуск одному треку, затем всем: запрет трека и обычный каталог при пустом пересечении.
6. Добавить ещё два заведения, проверить наследование и устройства, отсутствие новых подарков и текущую оплату. Заведение другого владельца и обычный клиент без подборки должны сохранить свои каталоги.
7. Перевыпустить ссылку: оба старых устройства получают отказ на новые audio/cover; новая ссылка работает, назначения сохраняются. Затем отозвать: отказ ссылки/витрины и обычный каталог в заведении. Другая подборка продолжает работать.
8. Проверить rollback на стенде после отката кода: подборки/привязки/аудио сохраняются, обычное добавление заведений работает. До этих проверок готовность к выпуску не подтверждена.
