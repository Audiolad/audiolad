## Путь данных и причины

Ссылки ниже относятся к итоговому дереву; пометка `HEAD до исправления` обозначает исходную версию текущей ветки.

1. **Факт:** `analyze-output.ts:40` выбирает normalized-документ из вывода Python. `execute.ts:233` строит признаки, а `execute.ts:243` сохраняет `{ ...collected.normalized, analysis_features_v1: features }`. Исходные legacy-поля при добавлении новых признаков не удаляются. Это не доказательство наличия конкретных полей у «Последней пластинки».
2. **Факт:** `features.mjs:41` принимает только массивы тегов. В `buildFeatures` используются `moods/mood_top` и `instruments/instrument_top` (`features.mjs:121`). Контейнеры `items/top`, другие legacy-алиасы или пустое основное поле могут дать пустой новый признак, хотя legacy-читатель поддерживает более широкие формы (`passport.ts:251`, `passport.ts:336`). Это возможная потеря при материализации, а не отсутствие ML-анализа.
3. **Факт:** API прогонов передаёт JSON без вырезания настроений/инструментов: `src/app/api/music-analyzer/runs/[id]/route.ts:18`, `contract.ts:85`. `RunDetail.tsx:65` читает паспорт из normalized JSON.
4. **Факт, воспроизведён регрессиями:** legacy-читатель намеренно пропускает `analysis_features_v1` (`passport.ts:137`), отдельно читая legacy и features. До исправления `MusicPassport.tsx:20–29` (`HEAD до исправления`) при наличии любого FeatureSet игнорировал fallback: null/объект/пустой массив в `features.mood/instruments` превращались в пустую карточку, даже если `passport.moods/instruments` содержали данные. Некорректный элемент `null` также мог вызвать ошибку рендера. Это самостоятельная ошибка чтения/рендера.
5. **Факт:** «Характер и настроение» отображает mood; «Характер звучания» отдельно читает `sound_character` и его алиасы (`passport.ts:756`, `MusicPassport.tsx:283`, `MusicPassport.tsx:292`). В схеме FeatureSet отдельного нового признака характера нет. При отсутствии исходного `sound_character` нельзя восстановить его из настроения или инструментов.
6. **Гипотеза для конкретного трека:** пустые признаки плюс сохранившиеся legacy-списки объясняют показанный владельцем симптом. Без normalized JSON нельзя отличить этот случай от реального отсутствия анализа или корректного withholding. Для окончательного диагноза нужно сопоставить исходные списки, feature.value, флаги и итоговые строки одного run ID.

## Почему появлялся «смешанный»

**Факт из сохранённого отчёта:** `eval-results-09d393ce.json:107` описывает для «Тихой гармонии» разрыв двух оценок `0.0079` при tie margin `0.0200`, после чего Python назначил `mixed`. `INVENTORY-09d393ce.md:45` фиксирует это правило закреплённого внешнего Python-репозитория. Сам Python-код здесь не расположен и в этом прогоне не проверялся по сети.

**Факт по приложению:** до исправления `features.mjs:112–123` (`HEAD до исправления`) переносил primary type, включая `mixed`, в публичный `vocal_role`. Исключение для близкой оценки речи касалось только primary=instrumental. Близость zero-shot сходств instrumental/vocal/mixed не подтверждает наличие голоса: инструменты, тембры и фон могут давать близкие сходства. Последнее объясняет механизм риска, но не устанавливает акустическую причину ошибки на «Последней пластинке».

## Что исправлено

Пустые/некорректные автоматические признаки используют безопасные legacy-строки. Списки только из удержанных тегов, удержанный признак целиком и ручной пустой список не восстанавливаются через fallback.
- `passport.ts:725`: до потери метаданных применяется существующий `sourceTagDecision`; конфликтующее withholding в одном прогоне удерживает тег. `tag-withholding.ts` и правила #980 не изменены. `features.mjs:53` теперь сохраняет исходный status тега при материализации, раньше status=withheld мог теряться.
- `MusicPassport.tsx:19`: общий resolver заменяет локальную реализацию; отсутствующие инструменты, настроение и характер показывают «не определено». Legacy average/max/rank сохраняются при fallback.
- `features.mjs:138`: `vocal_role` больше не назначается по одному `vocal.type` или близости классов. Требуются все четыре конечные оценки instrumental/vocal/spoken_word/mixed в 0–1, победитель ≥0.35 и отрыв ≥0.08. Для mixed дополнительно нужны vocal ≥0.35, vocal − instrumental ≥0.08 и mixed.segment_consistency ≥0.6. Иначе значение null, на экране «не определено». Инструменты вообще не используются как голосовой сигнал.
- Это **предварительные консервативные пороги сходства CLAP**, не вероятности, не валидированный VAD и не обещание точности классификации. Положительные метки остаются candidate с confidence=null и описанием ограничений. Независимых готовых VAD/PANNs/Demucs-сигналов в используемом локальном конвейере не найдено; новые модели/зависимости не подключались.
- `feature-overrides.ts:10`: endpoint признаков использует тот же безопасный reader, чтобы асинхронная загрузка истории не возвращала удержанные теги поверх первого рендера. Проверено с mock-хранилищем без доступа к БД.
- `features.mjs:160`: безопасная проекция при чтении распространяется и на сохранённые FeatureSet. Исходные JSON остаются неизменными, доступны в экспорте/Raw JSON. Ручной vocal_role сохраняется. История поправок применяется существующим `applyOverrides`; ручные списки, пустые списки и сброс проверены отдельно. Миграции не нужны.

## Совместимость и бизнес

Изменения не затрагивают локальный DSP, шкалу энергии, ритм/темп и динамику. Формат API, схема FeatureSet и поля исторических JSON сохранены; изменяется безопасная интерпретация автоматического vocal_role. Структурированные mood/instruments теперь читают и feature-only данные, а не только legacy. Сокращённые stored facts, альбом и контекст описания используют прежние формы данных. Исторические версии паспортов и ML-результаты не переписываются; массовый повторный анализ не запускается.

Для бизнес-подбора безопасно сохранять действующие ограничения на измеренный BPM и проверенные источники тегов. Настроения, инструменты и вокал CLAP пригодны как гипотезы для просмотра человеком. Их нельзя использовать как гарантированный фильтр «без вокала», доказательство пригодности площадке или медицинского эффекта. При null/withheld, конфликте с владельцем, близких оценках или требовании гарантированного инструментала нужен отказ от автоматического вывода и ручное прослушивание точного файла. Новая энергия остаётся предварительной оценкой и не становится measured confidence. Интерфейс и воронка пилота кофейни не менялись.
