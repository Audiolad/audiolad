# Продукты выпускников Школы аудиопрактик

На лендинге Школы после отзывов и внизу каталога платформы показывается ручная
подборка опубликованных продуктов. Администратор добавляет существующего автора,
выбирает до двух его продуктов, задаёт поток и порядок, включает показ. Данные
карточек читаются из каталога; скрытие или снятие продукта с публикации убирает
его из витрины при следующем запросе. Пустая витрина не рендерится.

## Размещение на платформе

**место требует подтверждения Сергея**

1. Реализовано: низ `/catalog`, только при отсутствии активного поиска и фильтров.
   Компонент не вмешивается в каталог и его карточки, легко переносится одним импортом.
2. Альтернатива: низ страницы «Стать автором», рядом с рассказом о Школе.

Общий серверный компонент: `SchoolGraduateShowcase`; представление:
`GraduateProducts`. На school.audiolad.ru ссылки ведут на основной домен АудиоЛада,
на платформе – относительные. Сторонних сайтов в новых ссылках нет.

## Данные и внедрение

Аддитивная миграция `20270106120000_school_graduates.sql` создаёт новую таблицу,
проверку выбора и RLS; не меняет существующие строки. Применить штатным процессом
деплоя. Список изначально пуст: Сергей подтверждает состав через
`/admin/school-graduates`. Новые авторы в списке выключены по умолчанию.
Лендинг живёт здесь же (`src/app/(platform)/school-site/page.tsx`), отдельная
интеграция не нужна. Дополнительно доступен `GET /api/school/graduates` на основном
домене с тем же публичным `CatalogCard` DTO, что у `/api/catalog`, без кеширования.
Школьный прокси по-прежнему не открывает маршруты платформы на school-хосте.

Полный отчёт записан в `REPORT.md` рабочей задачи, рядом с каталогом `wt`.

## Проверки

- Полный `npm run lint`: exit 0, 111 предупреждений в существующем коде; изменённые файлы проходят отдельно без предупреждений.
- `npm run typecheck`: exit 0 с Node 22 и heap 6 GiB.
- `npm run test:school-graduates`, существующие `catalog-listing-unit` и `school-proxy-routing-unit`: пройдены.
- PostgreSQL 17 в изолированной папке `/tmp`, single-user: новая миграция компилируется, тесты принадлежности автору, дубликатов, черновиков, порядка и очистки FK проходят. Проверки RLS под anon из SQL-теста требуют обычной изолированной БД: single-user всегда обходит права.
- `npm run build` заблокирован окружением: Turbopack не принимает внешнюю ссылку на локальные зависимости; webpack останавливается с `Could not parse output from TypeScript's --showConfig`.
- SSR-проверки подтверждают скрытие пустого блока, адреса ссылок, минуты, ограничение подназвания и классы сетки 1/2/3 колонки. Визуальная проверка на мобильном и десктопе, реальная авторизация в админке и переход на PDP остаются для стенда: Chromium в окружении отсутствует.

Production не затрагивался, миграция там не применялась. Push и открытие PR выполняет оркестратор.
