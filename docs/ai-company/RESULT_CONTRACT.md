# Result Contract

Задача запускается только когда понятно:
`зачем → какой результат → кто использует → зачем он ему → какую цель продвигает`.

## Обязательный Task Packet
- **Strategic Goal** — какой общей цели служит.
- **Why** — почему задача появилась.
- **Ideal Outcome Scene** — простая человеческая сцена идеального результата.
- **Expected Output** — конкретный конечный результат.
- **Deliverable Format** — форма передачи.
- **Producer** — кто производит результат.
- **Result Consumer** — кто использует его дальше.
- **Consumer Need** — что Consumer сможет сделать благодаря результату.
- **Acceptance Criteria** — проверяемые признаки готовности.
- **Market / Reference Check** — кто уже решал задачу и что можно использовать.
- **Human Gate** — где агент обязан остановиться.
- **Blocked** — есть ли блокировка.
- **Next Action** — что происходит после результата.

## Ideal Outcome Scene
До технического решения агент должен ответить:
> Если мы всё сделаем правильно, что произойдёт в реальной жизни конкретного человека?

Технический Done — промежуточный. Конечный результат находится в опыте пользователя.

## Best Result Check
Перед работой:
> Как выполнить задачу наилучшим образом для общей цели, пользователя и следующего Consumer — с максимальной ценностью при минимально необходимой сложности?

Перед handoff вопрос повторяется.

## Handoff
Каждая передача содержит: Task, Strategic Goal, Why, Expected Output, Actual Result, Deliverables, Result Consumer, Consumer Need, Best Result Check, Acceptance Criteria status, Open Questions, Risks и Next Action.

## Consumer Acceptance
Consumer отвечает:
- **ACCEPT** — результата достаточно для следующей работы;
- **RETURN** — чего не хватает, почему это блокирует и что исправить.

Definition of Useful важнее формального Done.

`Produced → Verified → Accepted → Used`.
