# VK Реклама – техническая готовность и аудитории кофеен

Задача `511c4b4b-3f61-4296-bf4c-762f3c6363a9`. Код подготовлен для review, **накопление аудиторий ещё не включено**. Реклама не запускалась, бюджет не назначался, deploy не выполнялся.

## Исследование и блокеры

- Поиск `_tmr`, `top.mail`, VK pixel, retargeting в репозитории не выявил установленного пикселя или ID. VK Bridge относится к mini app, а не к рекламному пикселю. Production-конфигурация и кабинет VK в этом окружении недоступны; существование пикселя там не исключено. Перед включением проверить кабинет и production, не создавать второй пиксель вслепую.
- `BaseProviders` подключает Яндекс Метрику и `AnalyticsConsentBanner` только на основном сайте. Business host обходит этот провайдер в root layout. Теперь единственный `VkAdsPixel` расположен в root layout и охватывает оба сайта, независимо от Метрики.
- `analytics-consent.ts` хранит локальное согласие браузера, баннер явно описывает **Яндекс Метрику**. `privacy/page.tsx`, раздел 8, также описывает Метрику. Email marketing consent – отдельная цель. Business legal consents и принятие оферты не являются разрешением на VK tracking. Источник утверждённого рекламного согласия ACCOUNT-level в checkout не найден.
- Поэтому root передаёт `accountAdvertisingConsent="unknown"`: **даже при наличии ID и разрешённой Метрике VK не загружается**. Это отдельный блокер согласия, не только отсутствие доступа к VK. Необходим существующий авторитетный источник состояния аккаунта (включая отзыв и выход). Не создавать новое согласие, localStorage-флаг, тексты или таблицы; подключить утверждённый механизм, когда будет указан его API/PR. Одной настройки ID недостаточно.
- Нет npm, gh и node_modules. Локальная документация `node_modules/next/dist/docs/` отсутствует; зависимости не устанавливались. Существующие паттерны Next App Router (`usePathname`, `Suspense`) сохранены.

## Настройка

Публичный числовой ID читается из `NEXT_PUBLIC_VK_PIXEL_ID`. Значение не придумано и не добавлено в env-файлы. Без ID адаптер выключен. Ops задаёт ID в окружении штатной сборки и выполняет согласованную публикацию: `NEXT_PUBLIC_*` в Next.js встраивается при сборке, изменения runtime env без пересборки недостаточно. Код менять для ID не нужно.

Источник разрешения должен передавать `granted` / `denied` / `unknown` из согласий текущего аккаунта, обновляться при отзыве и logout, не переиспользовать разрешение предыдущего аккаунта. По умолчанию unknown. До включения проверить также поведение уже загруженного vendor SDK при отзыве: адаптер останавливает собственные отправки, но не обещает остановить внутренние запросы SDK. Для полного прекращения SDK после отзыва нужен проверенный vendor opt-out либо перезагрузка страницы с denied. До проверки это ограничение блокирует включение.

`BusinessAccessLine` сообщает только coarse mode через локальное событие, без идентификаторов и дат. При изменении согласия адаптер запрашивает актуальное состояние повторно. Подарок реально выдаётся в `access-grants/apply.ts` → `activateBusinessTrial`, также через `business-workspace/load.server.ts` / `auth/business-return`; серверное событие `trial_started` уже существует. Для продаж достаточно наблюдаемого gift exclusion, для точной конверсии создания требуется отдельное подтверждение после успешной выдачи, не клик и не query-параметр.

`payment_success` нельзя отправлять по возврату от провайдера, URL `success` или наличию paid-доступа. Связать только с проверенным сервером новым успешным B2B-платежом после подключения согласий, с дедупликацией без отправки order/user ID. Пока событие зарезервировано, не считать его проверенным или работающим. Рабочий путь исключения плательщиков – наблюдаемый `subscription_active`; платежи без возврата клиента пиксель не увидит.

## Семантика и минимизация данных

- Общий factory `vk-ads.mjs`, единственный SDK `https://top-fwz1.mail.ru/js/code.js`. Не добавлять стандартный VK snippet или noscript поверх него.
- Начальный просмотр и SPA-навигация имеют один источник: `page()`. Соседние одинаковые hostname/path не дублируются (включая Strict Mode effects); возврат на прошлую страницу считается новым просмотром. Query/hash не считаются отдельной страницей. При выходе на исключённый маршрут dedupe сбрасывается.
- В API пикселя передаются только ID счётчика, очищенный origin/path, пустой referrer, coarse route group и allowlist goal. Нет email, телефона, имён, user/venue/order ID, токенов, цены, raw referrer или произвольных params. Вендор использует собственные cookie/технические данные – утверждать полную анонимность нельзя.
- Auth, recovery/reset, private platform cabinet, embeds, mini app, player devices, платёжные URL и динамические Business-ID пути исключены из маршрутов адаптера. Проверка выполняется заново на каждой отправке. Не накапливаются события до согласия и не воспроизводятся после него.
- После consent grant на открытой странице можно отправить текущий просмотр; прошлые клики не восстанавливаются. Наблюдения доступа повторяются на новом документе для актуализации exclusion audience.

## Рецепты аудиторий в кабинете

Это рецепты для создания, не утверждение, что аудитории уже созданы. Окна ниже – начальные предложения для настройки в допустимых пределах кабинета.

| Аудитория | Включить | Исключить |
|---|---|---|
| Посетители Атласа – 30 дней | `atlas_home OR atlas_page` | `gift_started`, `subscription_active`, подтверждённый `payment_success` |
| Каждая кофейня – 30 дней | URL содержит точный `/b/atlas-kofeen/<slug>` | Те же исключения |
| SEO / главная – 30 дней | URL соответствующих разрешённых страниц | Те же исключения |
| Тёплый интерес – 14 дней | `go_to_music OR go_to_funnel OR go_to_cabinet` | Те же исключения |
| Интерес к подарку без активации – 14 дней | `gift_interest` | `gift_started`, `subscription_active`, подтверждённый `payment_success` |
| Подарок / действующие клиенты – exclusion | `gift_started OR subscription_active` (максимальное подходящее окно), позже подтверждённый `payment_success` | Не использовать для продающего ретаргетинга |

Исключения – ограничения браузерного наблюдения, а не синхронизированный реестр аккаунтов. Старое наблюдение trial/paid может сохраняться дольше фактического доступа. Cookies, смена устройства, отказ от согласия, ad blockers, отсутствие возврата после оплаты и малый трафик снижают охват. На другом домене/устройстве не гарантируется склейка. Нет основания обещать размер базы или готовность открутки. До теста проверить фактическую доступность аудиторий и текущие минимальные пороги в VK; численные пороги здесь не фиксируются.

## Кабинет: привязка и финальная проверка без паролей

1. Владелец с имеющимся доступом открывает VK Рекламу → раздел пикселей сайта (обычно «Сайты» / «Пиксели»). Проверяет существующие счётчики, домены и доступы; берёт ID существующего. Если его нет – создаёт пиксель сайта, получает числовой ID из кода/карточки. Не копирует второй snippet на сайт.
2. Предоставляет исполнителю только ID или доступ ролью через штатное приглашение кабинета. Пароли, session cookies и токены не нужны. Использовать один пиксель на audiolad.ru и coffee.audiolad.ru, добавить/проверить домены в настройках. Legacy business.audiolad.ru проверить отдельно.
3. Ops задаёт env для штатной сборки. Подключение утверждённого ACCOUNT-level consent authority и проверка отзыва обязательны **до** включения. Никаких новых юридических текстов в этой задаче.
4. В карточке пикселя → события добавить JS-цели с точными именами из таблицы; не создавать автоматические правила, дублирующие JS-цели. `payment_success` пока не использовать как работающий источник.
5. На согласованном стенде проверить отсутствие запросов к mail.ru без согласия, после отказа, на auth/recovery, а также при разрешённой только Метрике. С рекламным согласием проверить SDK один раз, один начальный pageView, SPA вперёд/назад, повтор эффекта и query-only navigation. Проверить удаление секретов из URL/referrer/payload в Network, внутренние запросы SDK и отзыв/смену аккаунта.
6. Пройти все десять карточек, переходы к музыке, кабинету, MAX и Telegram; открыть подарок без подтверждения – только `gift_interest`. На тестовом аккаунте с реальным выданным подарком/paid-доступом проверить exclusion goals, не выполнять реальную оплату ради этой задачи. Сверить тестовые события в Pixel Detector / Network и карточке VK (возможна задержка).
7. Создать аудитории по рецептам. Сохранить evidence с временем, hostname и именами событий без PII. До первого рекламного теста подтвердить exclusions, объёмы, consent/revocation, отсутствие дублей и отдельно согласовать рекламный запуск/бюджет. В этой задаче кампании и бюджеты не создавать.

API: [официальная справка Mail.ru JS API](https://top.mail.ru/help/ru/api/jsapi), [справка VK о пикселе](https://ads.vk.com/help/articles/pixel). Прямое чтение страниц справки в окружении завершилось timeout/access error; контракт pageView/reachGoal подтверждён индексированным фрагментом официального Mail.ru API. Поступление в кабинет и фактическое поведение vendor SDK требуют финальной проверки владельцем.

## Проверки и точка продолжения

- `node scripts/vk-ads-unit.mjs` – PASS: gate unknown/denied, отсутствие ID, single SDK, начальный hit/SPA/back dedupe, query/hash/PII, allowlist, gift/paid observations, отсутствие ложного payment_success. Тест offline, VK не вызывается.
- `npm run lint`, `npm run build` – не запущены: `npm: command not found`. node_modules отсутствует. Новый тест также доступен как `npm run test:vk-ads` в штатном окружении.
- Браузерный сценарий, TypeScript и реальный SDK/VK cabinet – не проверены. Локальные unit tests не заменяют эти проверки.
- Следующий шаг: указать существующий источник рекламного согласия аккаунта, подключить его вместо unknown и проверить отзыв; затем ID/привязка в кабинете и стендовый smoke по пунктам выше. Незавершённое: реальный consent binding, payment_success confirmation, vendor revocation, полный lint/build/browser, приём в VK, создание аудиторий. Нельзя считать AC 2–6 полностью выполненными.
