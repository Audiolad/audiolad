# Cloud.ru Foundation Models: ключ и проверка доступа

- Только ввод ключа и проверка API на production-сервере Timeweb `72.56.232.160` от root. Без генерации статей и без деплоя. Секрет на сервере хранится только в `/etc/audiolad/cloudru-fm.env`; резервная копия — в менеджере паролей Сергея.
- Агенты ключ не видят и не запрашивают. Никогда не присылать ключ в чат, почту, GitHub или Company Core. Не делать скриншоты окна с ключом. Не включать запись терминала, `set -x`, вывод env-файла или HTTP-заголовков.
- OpenAI-совместимый endpoint: `https://foundation-models.api.cloud.ru/v1`. Авторизация: `Authorization: Bearer <Key Secret API-ключа>`. Бесплатный каталог: `GET /v1/models`.
- Для проб: `openai/gpt-oss-120b` — основной; `Qwen/Qwen3.6-35B-A3B` — второй кандидат. Справочно: `Qwen/Qwen3.5-397B-A17B`, `Qwen/Qwen3-Coder-Next`. Использовать только модели с размещением **«Внутренняя»**; внешние модели не вызывать.
- Источники: [каталог моделей](https://cloud.ru/docs/foundation-models/ug/topics/overview__available__models), [аутентификация](https://cloud.ru/docs/foundation-models/ug/topics/api-ref__authentication). Endpoint, ID моделей и цены сверены 23.10.2026 по документации и [тарифному приложению](https://cloud.ru/documents/tariffs/evolution/foundation-models); живой API в этой задаче не вызывался. Контекст и бюджет пилота: [исследование](../research/ru-ai-platforms-seo-factory-e3f7dd1e.md), разделы 5 и 8.

## Настройки в личном кабинете Cloud.ru

- Сервисный аккаунт `audiolad-seo-factory` на уровне проекта: минимальная роль, необходимая для Foundation Models. При `403` проверить роль именно в проекте; название роли уточнить в кабинете, не выдавать широкие права наугад.
- API-ключ: **Сервисы = только Foundation Models**; **Адреса = только `72.56.232.160`**; **Время действия ≈ 90 дней**. Записать дату ротации без секрета. При необходимости задать интервал работы.
- Key Secret показывается один раз: сразу ввести на сервере и сохранить в менеджере паролей, не пересылать.

## Безопасный ввод на сервере

- Переменные файла: `CLOUDRU_FM_API_KEY` — секрет; `CLOUDRU_FM_BASE_URL` — необязательный несекретный URL. По умолчанию URL уже задан в скрипте. Файл — `root:root`, `0600`. Ключ НЕ добавлять в `shared/.env.production`, `.env.local` Next.js или GitHub Secrets.
- В root-терминале выполнить:

```bash
install -d -m 755 /etc/audiolad
bash -c 'umask 077; IFS= read -rs -p "Key Secret: " k; echo; [ -n "$k" ] || exit 1; printf "CLOUDRU_FM_API_KEY=%s\n" "$k" > /etc/audiolad/cloudru-fm.env.tmp && chown root:root /etc/audiolad/cloudru-fm.env.tmp && chmod 600 /etc/audiolad/cloudru-fm.env.tmp && mv -f /etc/audiolad/cloudru-fm.env.tmp /etc/audiolad/cloudru-fm.env; unset k'
stat -c '%U:%G %a %s' /etc/audiolad/cloudru-fm.env
```

- Вставить секрет в невидимое поле `Key Secret:` и нажать Enter. В `~/.bash_history` останется только команда без значения: ввод читает `read`, а не оболочка командной строки. Значение не передаётся через argv или env дочерних процессов. Ожидаем `root:root 600 <размер>`; содержимое файла не выводить.
- Скрипт не исполняет env-файл: допускаются только две указанные переменные `KEY=VALUE`, пустые строки и `#`-комментарии. Поддерживается одна пара внешних кавычек и CRLF. Пустые ключи, пробелы и управляющие символы запрещены.

## Где взять скрипт

- После ближайшего production-релиза: `/var/www/audiolad-deploy/current/deploy/scripts/cloudru-fm-probe.sh`.
- До релиза: взять **точный SHA коммита main**, содержащего этот скрипт; заменить `<SHA>` в URL ниже. Это загрузка публичного скрипта без ключа, не запрос к API. Сначала проверить синтаксис:

```bash
curl -fsSLo /root/cloudru-fm-probe.sh https://raw.githubusercontent.com/Audiolad/audiolad/<SHA>/deploy/scripts/cloudru-fm-probe.sh
bash -n /root/cloudru-fm-probe.sh
```

## Проверка

1. Бесплатно, из релиза (для скачанного файла заменить путь на `/root/cloudru-fm-probe.sh`):

```bash
sudo bash /var/www/audiolad-deploy/current/deploy/scripts/cloudru-fm-probe.sh
```

- Ожидается `HTTP 200`, затем для каждого ID — `есть в каталоге`. `нет` означает неуспешную проверку: сверить точный ID, доступность и размещение модели в каталоге; платный вызов не начинать.

2. Перед платным запуском сверить цену в карточке модели и [тарифном приложении](https://cloud.ru/documents/tariffs/evolution/foundation-models). Затем:

```bash
sudo bash /var/www/audiolad-deploy/current/deploy/scripts/cloudru-fm-probe.sh --paid
```

- Скрипт покажет модели, `max_tokens=32`, оценку и запросит слово **ДА**. Без терминала требуется явное `CLOUDRU_FM_PROBE_CONFIRM=ДА`; обычный запуск Сергея — интерактивный.
- На каждую модель ровно один POST с фразой «Ответь одним словом: готово», `temperature=0`, `stream=false`. Ожидается HTTP 200, модель, `prompt_tokens/completion_tokens/total_tokens`, первые 80 символов ответа и оценка ₽ с НДС. Пустой content при расходе completion-токенов может означать reasoning; повтор автоматически не выполняется.
- `401/403`: проверить срок и значение ключа, сервис Foundation Models, разрешённый IP `72.56.232.160`, роль аккаунта в проекте. `402/429`: проверить баланс и лимиты; не запускать частые повторы. Другие коды: проверить параметры и доступность сервиса. Скрипт выводит только JSON `error.message`, максимум 300 символов, с маскированием ключа; заголовки и прочее тело не печатает.
- Код выхода `0` — все выбранные проверки прошли; иначе ненулевой. Ни ретраев, ни опроса в цикле, ни генерации статей.
- Настройки: `CLOUDRU_FM_ENV_FILE` меняет путь root-only файла; `CLOUDRU_FM_PROBE_MODELS` задаёт ID через пробел; `CLOUDRU_FM_PROBE_MAX_TOKENS` — целое 1..256 (по умолчанию 32). Не передавать ключ через окружение. Для модели вне таблицы платный запуск запрещён без `CLOUDRU_FM_PROBE_ALLOW_UNPRICED=1`; выводится «цена неизвестна, сверить в карточке модели». Это не подтверждает внутреннее размещение — его проверяет Сергей.
- Только для тестов: `CLOUDRU_FM_PROBE_ALLOW_LOCAL=1` разрешает `http://127.0.0.1:<port>/v1`; `CLOUDRU_FM_PROBE_SKIP_OWNER_CHECK=1` разрешён только вместе с этим флагом и фактическим локальным URL. Проверка прав остаётся. На production эти исключения не использовать. Нужны Bash, curl, python3 и GNU stat.

## Бюджет

- Потолок предоплаты пилота **3 000 ₽** из исследования; баланс служит выключателем расходов. Массовая генерация — только отдельной задачей с одобрением Сергея.
- Приложение №7.EVO.11.2, **версия 261023, действует с 23.10.2026**, ₽ с НДС за 1 млн токенов:

| Модель | Вход | Выход |
|---|---:|---:|
| openai/gpt-oss-120b | 15,86 | 61,00 |
| Qwen/Qwen3.6-35B-A3B | 219,60 | 329,40 |
| Qwen/Qwen3.5-397B-A17B | 915,00 | 1085,80 |
| Qwen/Qwen3-Coder-Next | 122,00 | 244,00 |

- Оценка: `(prompt_tokens × цена входа + completion_tokens × цена выхода) / 1 000 000`. При ≈20–40 входных и ≤32 выходных токенах на модель: gpt-oss-120b ≈0,00227–0,00259 ₽ (**<0,01 ₽**); Qwen3.6-35B-A3B ≈0,01493–0,01932 ₽ (**<0,02 ₽**). Это доли копейки для gpt-oss и около 1,5–1,9 копейки для Qwen; диапазоны посчитаны при 32 выходных токенах, при меньшем расходе дешевле.
- Это пропорциональная оценка, не гарантия списания: токенизация и округление биллинга могут её изменить. При увеличении max_tokens оценка растёт. Ночной тариф для Qwen существует, для пробы не нужен.
- Лимиты: 20 запросов/с на ключ, 20 параллельных запросов на организацию. Скрипт выполняет вызовы последовательно.

## Ротация и отзыв

- Создать новый ключ с теми же ограничениями. Ввести той же командой: файл заменится атомарно через `mv`. Пройти бесплатную проверку, затем отозвать старый ключ в кабинете. Обновить дату следующей ротации и запись в менеджере паролей.
- При подозрении на утечку сразу отозвать ключ в личном кабинете.
- Удаление локального файла: `shred -u /etc/audiolad/cloudru-fm.env` (или `rm /etc/audiolad/cloudru-fm.env`); это не заменяет отзыв в кабинете и очистку резервной записи. `shred` не гарантирует стирание копий на SSD/CoW/снапшотах.
- Следующий шаг после появления скрипта в main: Сергей выполняет безопасный ввод на сервере и бесплатную проверку, затем при необходимости подтверждает платную пробу. Эта задача сервер не меняет.
