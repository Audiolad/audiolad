# Конвейер на один альбом

Первый сегмент производства: от плана альбома до папки из 10 записей (исходники, паспорта, метаданные, лицензии или отметка об их ожидании) для **ручного** мастеринга в BandLab. Без автомастеринга, без автообложек, без публикации, без выкладки в АудиоЛад и в пул Бизнеса. Допуск в закрытый каталог – отдельные шаги 4–8 регламента stage3 и, когда будет готов, режим «только Бизнес».

Ниже – проект рабочего пути. Платные вызовы не запускать, пока Сергей не утвердит бюджет, ключ, тариф и ответы MusicGPT по приватности и лицензии.

## Вход

Готовый план одного альбома:

- 10 уникальных канонических названий;
- два промпта (вариант A и вариант B) и явные параметры: модель, инструментальность, запретные теги, целевая длительность (если её всё же удастся задать официально);
- кто правообладатель в лицензии (ожидаемо – ИП Петров С. С.);
- каталог закрытого хранилища, куда ляжет архив (не git, не открытый диск).

Схема вызовов, как в постановке: **5 API-генераций × 2 результата = 10 WAV**. Из них 3 вызова с промптом A (6 записей) и 2 вызова с промптом B (4 записи).

## Восемь шагов

### 1. Подтвердить тариф, условия и приватность на дату сессии

По шагу 1 регламента, до любой генерации:

1. Выбрать платный API-план с commercial use. Для моделей `v7` / `v7-pro` нужен **API Pro**.
2. Скриншот страницы плана / дашборда с датой и временем МСК; чек или письмо об оплате за период.
3. Сохранить копию Terms of Service и страницы API Pricing (PDF или веб-архив) с датой.
4. Получить письменное подтверждение MusicGPT (пока его нет – стоп для закрытого каталога): API-генерации не публикуются в Discover; их коммерческие права те же, что у платного веба; как получить Ownership License на API-трек.
5. Генерацию вести как приватную: не включать публикацию, не делиться ссылками, не класть CDN-URL в открытые места. Параметра Stealth в API нет – держимся подтверждения из п. 4 и дисциплины ссылок.
6. Ключ API хранить вне git.

**Стоп:** нет коммерческого тарифа на дату, нет чека/скриншота, нет копии условий, нет ответа по приватности – в Бизнес такие треки не планируем.

### 2. Зафиксировать план альбома (`album.json`) и журнал состояния

В закрытом хранилище создать папку альбома и файл плана до первого платного вызова. В плане – канонические названия, какой вызов (1–5) с каким промптом, модель, флаги, идемпотентный ключ каждого вызова (например `album_id` + `generation_index`). Журнал состояния: `planned` → `submitted` (есть `task_id`) → `downloaded` → `qc` → `accepted` / `rejected` → `licensed` / `license_pending` → `packaged`.

Повторный платный `POST` при уже известном `task_id` запрещён. Если сеть оборвалась после ответа с `task_id` – только опрос `byId` или ожидание webhook. Если ответа с `task_id` не было, не делать новый вызов вслепую: сначала сверка в дашборде / поддержке, чтобы не оплатить дважды. Параллельность не выше лимита плана (Plus 3, Pro 10; для пяти вызовов достаточно даже последовательного режима).

### 3. Сгенерировать пять задач через официальный API

Оркестратор (скрипт на нашей стороне, не ChatGPT как генератор) вызывает `POST /v2/MusicAI`:

- вызовы 1–3: промпт A;
- вызовы 4–5: промпт B;
- `make_instrumental` и прочие флаги – строго из плана альбома;
- `generate_album_cover`: false;
- `title` в API можно передать техническое имя вызова, но канонические 10 названий **не считать** назначенными на этом шаге: у одного вызова два выхода и одно поле `title`;
- `webhook_url` – наш закрытый приёмник, если он есть; иначе только polling `byId`.

Сохранить полный промпт, сырой запрос без ключа, сырой ответ, `task_id`, `conversion_id_1`, `conversion_id_2`, `credit_estimate`, модель, дату и время МСК.

### 4. Скачать исходные файлы и посчитать хеши

Как только статус `COMPLETED`, сразу скачать оригинальный WAV каждого `conversion_id` (и MP3 как дополнительную копию, не вместо WAV). Файл не перекодировать и не переименовывать «поверх»: исходное имя и URL (без публикации) записать в метаданные, в архиве хранить байты как пришли. SHA-256 считать по файлу на диске. WAV с CDN живёт 7 дней – пропуск срока = риск потерять исходник.

Если WAV не пришёл – стоп по этой записи, не подставлять самостоятельно сконвертированный файл как «исходник сервиса». Конвертер API допустим только как запасной путь с пометкой в паспорте, что это уже не оригинальный байтовый поток Music AI, и только после решения Сергея.

### 5. Слушать, отбирать и назначить канонические названия

Перемешивание – это назначение 10 выходов на 10 позиций альбома, **без правки звука**. Сергей слушает все 10. Неудачный выход не считается треком альбома. Перегенерация – только выборочно, с явной сметой и согласием на расход, новым `generation_index` и новой папкой, без затирания отклонённого исходника (он остаётся в доказательствах).

Только после приёмки каждой позиции записывается `canonical_title` и порядковый номер 1–10.

### 6. Получить Ownership License PDF – вручную, пока нет API

Для каждого принятого трека:

- если MusicGPT официально подтвердит способ получить PDF на API-трек (или трек виден в веб-кабинете того же аккаунта) – скачать оригинал, **не править**, сохранить имя, дату, SHA-256;
- если способа нет – в манифесте и паспорте: «ожидает ручного получения», без выдуманного бланка.

Лицензия должна быть на верного субъекта (ИП). Если в PDF другой адресат или другое юрлицо оператора, чем в ToS, – стоп и вопрос юристу. PDF не правим.

### 7. Собрать папку записи, паспорт и манифест

Структура архива (закрытое хранилище):

```
album-<код>/
  album.json              # план
  manifest.json           # итог: 10 позиций, статусы, хеши
  state.json              # журнал состояния
  evidence/               # скрин тарифа, чек, копия ToS и Pricing на дату
  track-01-<slug>/
    source/<оригинальный.wav>
    source/<оригинальный.mp3>          # если скачан
    license/<оригинал.pdf>             # или LICENSE_PENDING.txt
    prompt.txt
    generation.json                    # task_id, conversion_id, модель, даты, сырые ответы без ключа
    hashes.sha256
    passport.md                        # по шаблону пилота PR #1261
  track-02-...
```

Поля на трек, совместимые с паспортом PR #1261 и постановкой задачи:

| Поле | Куда |
|---|---|
| `canonical_title`, `ordinal` | манифест, паспорт § 1 |
| `prompt_variant` A/B, полный текст промпта, итерации | `prompt.txt`, паспорт § 3 |
| `generation_task_id`, `conversion_id` | `generation.json`, паспорт § 3 |
| `license_id` (если сервис его даст) | паспорт, манифест; иначе «не найдено» |
| `source_audio_url` (служебно, не публиковать) | `generation.json` |
| `original_audio_filename`, SHA-256 WAV, размер, дата | `hashes.sha256`, паспорт § 5 |
| SHA-256 оригинального PDF | там же; если файла нет – «ожидает ручного получения» |
| `created_at` (время сервиса и МСК) | паспорт § 3 и § 7 |
| Исходное имя / каноническое имя | манифест |
| Модель, тариф, дата условий | паспорт § 3 |
| Вклад человека: А или Б | паспорт § 4 (честно; для чистой генерации без правок текста – обычно А) |
| Статус лицензии | `licensed` / `license_pending` |

Проверки Shazam, AcoustID и собственный отпечаток – по шагам 6–7 регламента, уже на этом архиве, до допуска в каталог. В первый сегмент конвейера они входят как подготовка паспорта, не как публикация.

### 8. Передать на ручной мастеринг, не публиковать

Итог сегмента: закрытый архив из принятых треков (цель – 10; меньше, если часть отклонена и ещё не пересобрана). Дальше человек мастерирует в BandLab. Мастер, повторный хеш, хранение в неизменяемом архиве, допуск в закрытый каталог «только Бизнес» – следующие сегменты, не этот PR и не этот запуск.

## Правила оркестратора (кратко)

- только официальный API `api.musicgpt.com`;
- идемпотентность на уровне альбом / индекс генерации;
- безопасные повторы только для чтения (`byId`, скачивание уже выданного URL);
- не создавать новую генерацию по таймауту, если `task_id` уже известен;
- контроль сметы: не превышать заранее согласованный потолок (число вызовов × 2 × ставка + запас на перегенерацию);
- никакой автопубликации и никакой загрузки в открытый АудиоЛад.
