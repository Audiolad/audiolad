# Шаблон «Паспорт записи»

Паспорт записи – один документ на одну фонограмму. Он собирает в одном месте всё, что нужно, чтобы показать: кто изготовитель записи, как она создана, где она была опубликована и на каком основании заведение её включает. Паспорт не заменяет договоры и не создаёт права сам по себе, он только собирает доказательства.

Правила заполнения:
- в каждое поле – только факт с источником (таблица базы, файл, страница, дата проверки);
- если факта нет – пишем «нужно от Сергея» или «не найдено (что проверяли, когда)»;
- ничего не дописываем «по памяти» и не угадываем;
- хэши считаем по самим файлам, а не копируем из интерфейса;
- время – МСК.

Связь с тем, что уже есть в АудиоЛад: в базе уже есть технический «паспорт» трека (`music_passport_versions` и `music_passport_attributes`): хэш файла, версия анализатора, BPM, тональность, жанры, громкость. Он отвечает на вопрос «что за звук». Паспорт записи ниже отвечает на вопрос «чья это запись и откуда она». Технический паспорт входит в него как раздел 6.

---

## 1. Идентификация

| Поле | Что писать | Источник в АудиоЛад |
|---|---|---|
| Название трека | Как на сайте | `audio_items.title` |
| Альбом | Название и ссылка | `practices.title`, `/practice/<автор>/<альбом>` |
| Проект (псевдоним) | Имя проекта | `authors.name` |
| Внутренний ID | Код AL-T-… и UUID | `audio_items.music_track_code`, `audio_items.id` |
| ISRC | Если присвоен; иначе «нет» | в базе поля нет |
| Длительность | Секунды | `audio_items.duration_seconds` / файл |
| Исходное имя файла | Как загружено | `audio_items.original_file_name` |

## 2. Правообладатель

| Поле | Что писать |
|---|---|
| Изготовитель фонограммы | ИП Петров Сергей Сергеевич (ст. 1322 ГК РФ: лицо, взявшее на себя инициативу и ответственность за первую запись) |
| Автор музыки / текста (если есть произведение) | Петров Сергей Сергеевич или «произведения нет / под вопросом» – по оценке из раздела 4 |
| Основание прав в АудиоЛад | Тип и ссылка из `music_rights_grants` (`source_type`, `source_reference`, `valid_from`) |
| Договоры с РАО / ВОИС / другими ОКУП | Есть / нет / неизвестно |
| Договоры с дистрибьюторами, лейблами, библиотеками | Есть / нет / неизвестно |

## 3. Создание

| Поле | Что писать |
|---|---|
| Инструмент генерации | Сервис и версия модели (например, Suno v5), либо «живая запись», либо DAW |
| Тариф на дату создания | Название тарифа, период оплаты |
| Условия сервиса | Версия / дата условий, действовавших на дату создания, и ссылка на сохранённую копию |
| Дата и время создания в сервисе | Из карточки трека сервиса или экспорта |
| Ссылка на трек в сервисе | Ссылка и статус (публичный / по ссылке / приватный) |
| Промпты | Полный текст стиля и описания, все итерации |
| Исходные файлы из сервиса | Имя, размер, SHA-256 |

## 4. Вклад человека и оценка авторства

| Поле | Что писать |
|---|---|
| Текст песни | Есть / нет; кто автор; где черновики |
| Правки | Что сделано руками: выбор вариантов, нарезка, сведение, мастеринг, аранжировка, замены частей |
| Инструменты правки | DAW, плагины, проекты |
| Оценка авторства | Кратко: есть ли творческий вклад человека, достаточный для произведения (ст. 1257 ГК РФ, Пленум № 10 п. 80). Пометка «предварительно, оценивает юрист» |

## 5. Файлы и хэши

Для каждого файла: роль (исходник сервиса / мастер / поток / старый mp3), имя, размер в байтах, SHA-256, дата появления, где лежит (без прямых ссылок с токенами).

## 6. Технический паспорт АудиоЛад

Версия паспорта, статус, хэш источника, версия анализатора и коммит, дата активации. Совпадает ли хэш паспорта с хэшем файла.

## 7. Хронология

| Событие | Дата МСК | Источник |
|---|---|---|
| Создание в сервисе | | |
| Загрузка в АудиоЛад | | `audio_items.created_at` |
| Первая публикация альбома | | `practices.first_published_at` |
| Основание прав в базе | | `music_rights_grants.valid_from` |
| Допуск в Бизнес | | `business_content_admissions` |
| Первое воспроизведение в заведении | | `playback_usage_facts`, `usage_kind = business` |

## 8. История публикации

Где запись была доступна публике: АудиоЛад (каталог, в списке / по ссылке / закрыто), поисковики, стриминги, видеоплощадки, сервис генерации, дистрибьюторы. Для каждой находки – дата проверки и источник. Пустой результат тоже фиксируется: «искали там-то, такого-то числа, не нашли».

## 9. Отпечаток и эталон

Ссылка на эталонный мастер (хэш), отпечаток (библиотека, версия, параметры, хэш файла отпечатка), дата снятия.

## 10. Цепочка лицензии до заведения

Изготовитель → (договор) → АудиоЛад / ИП → (договор / оферта АудиоЛад Бизнес) → заведение. Для каждого звена: документ, версия, дата, кто принял. Плюс уведомления по ст. 1244 п. 4: дата отправки, дата получения, дата вступления в силу (получение + 3 месяца).

## 11. Перечень доказательств

Список файлов с хэшами: скриншоты, экспорты, письма, чеки, договоры. Для каждого: что доказывает, кто сделал, когда, где хранится.
