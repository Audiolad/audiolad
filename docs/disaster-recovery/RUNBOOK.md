# Аварийный контур для оператора

Это инструкция для Сергея. Команды ниже не нужно выполнять, пока не принято Human Gate HG-745-1 и отдельно не разрешено переключение production. Сейчас GitHub остаётся основным.

Проверка, что сайт жив, в браузере или одной командой на любой машине:

```text
https://audiolad.ru/api/health/build
```

В ответе должно быть `"status":"ok"`. Поле `deployCommit` — какой коммит сейчас в проде. Это не секрет.

## GitHub работает, ChatGPT / Cursor / Grok нет

Сайт не меняется. Деплой через GitHub Actions по-прежнему доступен: Actions → Production Deploy → branch `main` → `confirm=DEPLOY`. Код можно править локально и пушить в GitHub без западного чата. Аварийный VDS для этого не нужен.

## GitHub недоступен: где код

Код должен лежать на `git.audiolad.ru` (Gitea на отдельном VDS). Пока Human Gate не закрыт, этой машины нет: последняя копия — GitHub и уже выложенный релиз на production. Новый коммит взять неоткуда, и это честный статус, а не скрытый запасной сервер.

Когда зеркало уже ведётся, репозиторий: `audiolad/audiolad`. Ветка `main`. `music-analyzer` попадает в то же зеркало, когда источник доступен учётной записи.

## GitHub Actions недоступен: как выпустить релиз

Выпускается тот же production-механизм, не новый скрипт сборки:

```text
sudo -n /usr/local/sbin/audiolad-deploy <40-символьный-sha>
```

Аварийный раннер только проверяет SHA, предка `main`, предка текущего production и затем вызывает эту команду. Подтверждение строго `EMERGENCY_CI`. Пользователь SSH только `deploy`. Произвольной команды он не принимает.

Это заработает при недоступном GitHub только после отдельного разрешения перевести `origin` production-копии на Gitea. До этого разрешения `retarget-origin.sh` production-каталоги отвергает.

## Западные AI недоступны

Сайт, вход, каталог, оплата и почта остаются на своих ключах на production. Писать код можно в локальном редакторе. Выпуск релиза идёт через GitHub Actions, пока GitHub жив, либо через аварийный раннер, когда он уже введён. Модель для этого не нужна.

## Откат

Откат не пересобирает приложение и не откатывает базу. Это существующий скрипт:

```text
/var/www/audiolad-deploy/scripts/rollback.sh
```

Аварийная обёртка просит подтверждение `EMERGENCY_ROLLBACK` и причину из букв, цифр и пробелов. Она не удаляет релизы и не выполняет произвольную строку.

После отката снова открыть `https://audiolad.ru/api/health/build` и убедиться, что `deployCommit` стал предыдущим.

## Возврат с аварийного Git на GitHub

Когда GitHub снова доступен, коммиты аварийной `main` отправляются только fast-forward. Если истории разошлись, скрипт останавливается и ничего не переписывает. Принудительный push в `main` запрещён.

## Что не делать руками

- Не покупать второй сервер кроме HG-745-1 и не менять DNS `audiolad.ru`.
- Не делать `git push --force` в `main`.
- Не делать `git reset --hard` в `/var/www/audiolad-clean`.
- Не запускать `deploy.sh` из каталога `current`.
- Не править Nginx, PM2 и Docker на production ради зеркала.
- Не класть `.env.production` и платёжные ключи на Git-хост.
- Не открывать root shell агенту или веб-форме.
- Не мержить этот PR и не переключать production, пока ревью фазы 1 отдельно это не разрешит.
