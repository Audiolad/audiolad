# Human Gate HG-745-1

Единственный внешний блокер фазы 1. Пока этого решения нет, скрипты работают на одноразовом Gitea и на локальных git-репозиториях. Production не переключается.

## Что купить и куда направить DNS

Один VDS в Timeweb Cloud, не текущий production `72.56.232.160`.

| Поле в панели | Значение |
|---------------|----------|
| Имя | `audiolad-emergency-git` |
| Регион | Россия, Москва или Санкт-Петербург |
| ОС | Ubuntu 24.04 LTS |
| CPU | 2 vCPU |
| Память | 4 GB |
| Диск | 80 GB NVMe |
| Публичный IPv4 | да |
| Назначение | Gitea, зеркала git, кэш npm-tarball. Не сайт и не GPU. |

Текущий pack репозитория около 92 MiB. 80 GB хватает на историю, `music-analyzer`, когда он станет доступен, кэш 504 npm-пакетов и несколько рабочих копий CI. Точную цену показывает калькулятор Timeweb в момент заказа; в репозиторий она не записывается.

DNS в том же решении, отдельной покупкой не является:

| Поле | Значение |
|------|----------|
| Тип | A |
| Имя | `git.audiolad.ru` |
| Значение | публичный IPv4 нового VDS |
| TTL | 300 |

Запись `audiolad.ru` не менять.

Firewall нового VDS: `22/tcp` (SSH администратора), `2222/tcp` (Git SSH), `443/tcp` (Git HTTPS). Порт `3000` не открывать. Nginx production на этот адрес не направлять.

## Что сделать Сергею

1. В Timeweb создать VDS с полями выше.
2. Создать A-запись `git.audiolad.ru`.
3. Написать в PR адрес IPv4 и подтверждение, что DNS создан.
4. Не копировать на этот VDS `.env.production`, service role и платёжные ключи.
5. Не менять `origin` в `/var/www/audiolad-clean` и не запускать деплой с этого PR.

После подтверждения следующий шаг, уже не эта поставка: поставить Gitea по `deploy/emergency/gitea/app.ini.example`, завести приватные репозитории из манифеста и положить `EMERGENCY_GIT_*` в GitHub Actions. До этого workflow `Emergency Git mirror` при ручном запуске останавливается и ничего не отправляет.

Переключение production `origin` на Gitea этим gate не разрешено.
