# Фаза 2 — точка интеграции, без реализации

Фаза 2 не строится в этой поставке: нет GPU, нет чата и нет фиктивной формы.

Стабильные «руки» уже лежат в репозитории и не зависят от модели:

| Действие | Команда | Чего она не делает |
|----------|---------|--------------------|
| Статус зеркала | `mirror-validate.sh` | Не пушит и не деплоит |
| План релиза | `ci-runner.sh --plan` | Не вызывает SSH |
| Пуск релиза | `ci-runner.sh --execute` только с `EMERGENCY_CI` | Только `audiolad-deploy <sha>` |
| План отката | `emergency-rollback.sh --plan` | Не переключает `current` |
| Здоровье | `GET https://audiolad.ru/api/health/build` | Читает публичный JSON |

Их вызывает один адаптер. У адаптера нет произвольного shell и нет передачи текста модели в argv. Модель выбирается снаружи адаптера:

1. Текущий западный агент, когда он доступен.
2. Российский API-совместимый endpoint, когда западный недоступен. Контракт тот же: план, не shell.
3. Локальная открытая модель на отдельной машине — последний резерв. В фазе 1 машина не заказывается.

Страница `company.audiolad.ru/emergency` в будущем показывает четыре состояния из runbook (GitHub жив / GitHub нет / Actions нет / модели нет) и кнопки, которые вызывают только план. Существующая страница `/admin/ai-company` читает `COMPANY_CORE_URL` или `COMPANY_API_URL` и `COMPANY_API_TOKEN`. Аварийные кнопки не встраиваются в этот токен и не получают его права на базу.

Кнопка «выпустить релиз» остаётся отдельным подтверждением человека и попадает в audit-log так же, как `ci-runner.sh`.
