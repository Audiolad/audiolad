# Персональные музыкальные подборки – задача 73b4869d

## Аудит и план до реализации

Исходная реализация продолжена в ветке `feat/coffee-personal-collections` с незакоммиченными правками; существующая работа сохранена. Production, инфраструктура, тарифы и юридические тексты не меняются.

- `business-app/guest/coffee`, `guest-coffee/load.server.ts`: обычная гостевая витрина открывает только публичные бесплатные альбомы, имеет собственный счётчик прослушивания. Она не подходит для выдачи закрытого каталога.
- `business-workspace/load.server.ts`, `sign.server.ts`: кабинет проверяет сессию, период доступа, выбранное заведение, допуск направления, паспорт и права. Подписание использует существующий master/delivery asset. Закрытые обложки обслуживаются серверным proxy.
- `BusinessGuestStartCta`, `business-guest/start.ts`, `/auth/business-return`: явное согласие с действующей офертой запускает существующий подарок. Открытие персональной витрины не должно вызывать эти функции.
- `business-app/login-access.ts`: привязка почты повышает тот же anonymous account, сохраняя user id.
- `pilot-slots.ts`, миграции `business_venue_slots_systemic`, `business_venue_self_serve_ten`, `business_shared_venue_renewal`: управление несколькими заведениями реализовано, лимит читается из БД (10 в последней миграции), есть выбор заведения, отдельные периоды, подключение устройств и общее продление. Подарок относится к первому заведению, дополнительные следуют текущим правилам.

План минимальных изменений: новые service-only таблицы подборок, элементов и привязок аккаунтов; административная форма рядом с закрытым каталогом; персональная страница в текущем coffee shell; существующие SpaOnlinePlayer, FadingAudio, BusinessCabinetMiniBar и кнопки треков. Добавить только маршруты ссылки, аудио и обложек в host allowlist. Использовать существующую кнопку подарка и сохранить подборку при получении сессии. Не менять обычный гостевой каталог и оплату.

## UX и доступ

Администратор выбирает допущенные альбомы целиком или отдельные треки, указывает название (например, «Подборка заведения») и получает одноразово показанную секретную ссылку. Порядок треков фиксируется при создании. Новые треки альбома автоматически не добавляются. Файлы не копируются.

Ссылка обменивается на host-only HttpOnly/Secure/SameSite=Lax cookie и перенаправляет на `/collection` без секрета в адресной строке. В БД хранится SHA-256 секрета (256 бит случайности). Ссылку нельзя восстановить из административного списка. Администратор может перевыпустить ссылку той же подборки: атомарно заменить хеш и снять отзыв. Новая ссылка показывается один раз с полем и кнопкой копирования; старые cookie больше не дают доступ. Ссылка не расходуется при открытии и работает одновременно на независимых устройствах владельца и приглашённых слушателей.

Предпросмотр – отдельное состояние: без регистрации, оплаты, подарка и отчётов воспроизведения заведения. Полные треки идут последовательно через существующий online engine. Каждый запрос аудио/обложки проверяет разрешение, отзыв и актуальные допуски. Клиент не получает storage path или подписанный storage URL. Никакого доступа к другим подборкам или полному закрытому каталогу.

Зелёная кнопка «Подключить заведение – 7 дней в подарок» (`business-app-btn business-app-btn-cta`) использует существующее подтверждение оферты и активацию. Если быстрый гостевой старт выключен, используется существующая регистрация с coffee return. Cookie переживает этот переход; при получении аккаунта выбор сохраняется по проверенному user id, включая anonymous account. При повышении anonymous account id остаётся прежним. В кабинете появляется ссылка на сохранённую подборку. Уже зарегистрированный пользователь также сохраняет выбор. Это не расширяет коммерческие права и не даёт подарок повторно.

## Границы и пробелы multi-venue для описания PR

Поддержка нескольких заведений подтверждена анализом кода и миграций, а не запросами production. Без применённых миграций/при ошибке чтения лимита действует одно заведение. Реальную оплату, создание трёх заведений, устройства и состояние флагов нужно проверить на тестовой БД перед выпуском. Подборка закрепляется за аккаунтом, а триггер заполняет пустые назначения его заведений направления cafe. Новое заведение наследует последнюю активную подборку владельца; существующее другое назначение сохраняется. `loadWorkspaceCatalog` пересекает обычный допущенный каталог с `business_personal_collection_location_tracks(locationId)`. Это распространяется на кабинет, очередь, выдачу треков и привязанные устройства без изменения движка зала. Отзыв или пустое пересечение возвращает обычный допущенный каталог; ошибка RPC даёт недоступность. Автоматическая синхронизация уже загруженной очереди на устройствах и реальные сценарии оплаты нескольких заведений требуют стендового прохода.

Отзыв запрещает новые запросы и останавливает открытый плеер при очередной проверке (каждые 15 секунд); уже полученные браузером байты невозможно отозвать. Сервер не обещает удаление уже прослушанного содержимого с устройства.
