# Сценарии, информационная архитектура и переходы

Проектное предложение Phase 1. Персона: владелец одной SPA-точки, одна основная зона, часто проверяет статус с телефона между делами. Имя «Анна», точка «Тихий сад» и программа «Тихое пространство» в preview вымышлены.

## Строгое разделение поверхностей

| Поверхность | Задача | Содержание | Граница |
| --- | --- | --- | --- |
| Owner Dashboard | Понять состояние и следующий шаг | Главная/статус; Точка и лицензия; Помощь; Профиль | Никакого локального автозвука; сводка не выдаёт heartbeat за звучание; не имитировать удалённую команду |
| Venue Player | Воспроизведение на устройстве с колонками | Программа, текущий трек, play/pause, ошибка/пусто/нет подключения | Честная локальная фаза плеера; отдельное подтверждение будущих команд владельца. В preview лишь отдельный экран устройства, звука нет |
| Enterprise Console · позже | Управление сетью | Много точек, роли/команда, массовые политики, fleet-отчёты | Отдельный будущий продуктовый контур, вне меню владельца одной точки; ни маршрутов, ни реализации в Phase 1 |

«Атмосфера и время суток» — обзор концепции будущих предпочтений Owner; применение и исполнение расписания в Venue ещё не спроектированы как рабочий контракт. В preview экран можно выбрать для рассмотрения, элементы внутри не кликабельны. Доступ к макету плеера означает переключение изображения поверхности, а не удалённое управление реальным устройством.

## Предлагаемая IA

Owner: Главная → сводка связи/звучания → ссылка на плеер; Точка и лицензия → сведения точки / отдельно документ; Помощь → простые шаги / диагностика; Профиль → аккаунт. Концепт атмосферы показан отдельно для согласования, не обязательный шаг ежедневной работы. Настоящее меню и существующие URL не меняются; в preview используются local-state кнопки.

## Сценарии и выходы

| Ситуация | Поток | Успешный выход / неопределённость |
| --- | --- | --- |
| Начало дня | Владелец → Главная → проверка источника/возраста статуса → при необходимости устройство точки | Статус подтверждён только соответствующим сигналом; при отсутствии данных «не удалось проверить» |
| Запуск на точке | Сотрудник у колонок → Venue Player → доступная программа → явный жест запуска → loading → playing или ошибка | Только успешный start даёт локальное playing; accepted PoP показывается отдельно от звука |
| Пауза на процедуру | Устройство → Пауза → paused → Продолжить по жесту | Owner не подменяет реальную паузу собственной анимацией. В preview кнопка меняет только сценарий |
| Пустая программа | Главная / Player → «нет доступной музыки» → помощь | Нет подставного трека, «успешного запуска» или вывода о лицензии |
| Пропал интернет | Нет подключения → статус звучания неизвестен → проверка интернета на устройстве → повторная проверка будущим реальным запросом | Онлайн-пилот не обещает продолжения из кеша. Нельзя обозначать это как автономную работу |
| Ошибка | Ошибка чтения / запуска → понятная причина и помощь → повторить после восстановления | Последнее известное состояние помечается устаревшим; не рисовать «всё хорошо». Preview не имитирует успешный retry |
| Проверка документа | Точка и лицензия → сведения + документ со scope/сроком/источником, когда появится | До интеграции «нет подтверждённых данных»; в preview нет скачивания |
| Изменить атмосферу | Рассмотрение концепта → согласование → отдельная техническая стадия | Никакого «сохранено» или влияния на музыку в Phase 1 |
| Нужна помощь | Главная/Player → Помощь → чек колонок/громкости, подключения, сообщения плеера | FAQ открывается локально. Отправка заявки и диагностики — «Концепт · позже» |

## Модель состояний для будущей интеграции

Держать отдельно: доступ; загрузка источника; связь устройства; локальный playback; freshness; права трека; документ точки. «Нет музыки» — успешно полученный пустой список. «Ошибка» — запрос не завершился успешно. «Offline» — потеря связи, не факт остановки. «Пауза» — подтверждённое локальное состояние, не stale heartbeat. Начальная загрузка — нейтральный текст без положительного статуса и без трека; отзыв доступа — 404 до рендера / прекращение выдачи защищённых данных. Эти правила — acceptance criteria следующих стадий, а не новый engine в этой задаче.

## Согласование на макете

Рассмотреть все 6 экранов × 5 состояний × 2 рамки (60 комбинаций), особенно 360px и телефон 390px. Общая карточка сценария видна на каждом экране, чтобы неизвестное звучание не терялось при переходе к документам или профилю. Значения статуса относятся только к музыке, не меняют юридический статус или аккаунт.
