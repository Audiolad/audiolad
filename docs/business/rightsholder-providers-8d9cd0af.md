# Выбор сервиса в первичной проверке правообладателя (8d9cd0af)

Автор выбирает **один** свой опубликованный продукт и трек, затем — где сделана музыка:

| Сервис | Обязательно | Файлы | «Посмотреть пример» |
|---|---|---|---|
| Suno | ссылка `https://suno.com/s/…`, ссылки/ID генераций треков продукта (`generation_refs`) | 2: скриншот генерации + подтверждение оплаченного периода | реальные обезличенные скриншоты (как раньше) |
| MusicGPT | тариф (`plan_name`); номер лицензии и ссылка — по желанию; пояснение, если на тарифе нет лицензии | 2: скачанная лицензия / паспорт трека + данные тарифа | текстовый пример, без скриншотов |
| Другой сервис / своя студия | название сервиса или описание, как сделан трек (`ai_service_other`) | 1–2: материалы создания и/или лицензия, условия сервиса, чек | текстовый пример, без скриншотов |

Правила не меняются: неограниченные повторные отправки после отказа/запроса уточнений, никакого автоматического `verified` (решает модератор), одна проверка не подтверждает права на весь каталог — eligibility каждого трека независима.

## Схема — нужна миграция

Текущая схема не позволяла хранить выбор без миграции: `service_track_url` был `NOT NULL` и для «своей студии» ссылки может не быть; не было места для ссылок/ID генераций и тарифа; `submit` требовал ровно 2 файла разных видов.

`20270102120000_business_rightsholder_providers.sql` — **только аддитивно**:

- `provider_details jsonb NOT NULL DEFAULT '{}'` (CHECK: объект, ≤16 КБ); ключи проверяются по сервису;
- `service_track_url` — `DROP NOT NULL` (ослабление) + новый CHECK: для Suno ссылка обязательна; прежний CHECK формата Suno сохраняется;
- новые RPC `author_business_verification_draft_v2` / `author_business_verification_submit_v2` и внутренний helper `business_onboarding_provider_error`. Старые RPC, таблицы, строки, политики не переписываются (legacy-строки получают `'{}'`).

Attempts-снимок автоматически содержит `ai_service` и `provider_details`.

Откат (вручную, после бэкапа): `docs/business/rightsholder-providers-8d9cd0af-rollback.sql`; отказывается выполняться, если есть непустые `provider_details` или строки без ссылки (`business_providers_rollback_refuses_data_loss`).

**Порядок выката:** миграция применяется ДО деплоя кода (страница читает `provider_details`, форма вызывает `*_v2`). Требует отдельного одобрения Сергея.
