# План проверки: Единое коммерческое соглашение 2.0

Проверка на пробной БД (восстановленная копия, шаг 2 плана раскатки) и на staging. **Не на production.**
Каталоги: собственная музыка Сергея — **Aurafon** и **Jazz Relax**.

## Автоматические тесты (локально, бокс)

- `npm run test:unified-agreement`
  - `scripts/unified-agreement-sql-unit.mjs` — PostgreSQL 17, одноразовая БД: миграция ×2, вставка 2.0 ×2, переключение ×2,
    grace, Бизнес только при личной 2.0, submit_v3 (+ отказ в режиме сопровождения), opt-in закрыт, синхронизация
    (dry-run, реальная, повтор, чужой правообладатель, блок по треку → отзыв), RLS, исторические строки неизменны, откат.
  - `scripts/unified-agreement-unit.mjs` — текст/хэш/реквизиты, логика гейтов, два статуса, флаг, проводка UI.
- `npm run test:support-consent-block` (PR 1) — по-прежнему проходит.

## Ручная проверка (staging, флаг ON)

| № | Сценарий | Ожидание |
|---|----------|----------|
| 1 | Флаг OFF, открыть /author-terms, /author-dashboard/business | Всё как сейчас (1.2, две галочки в Бизнесе) |
| 2 | Флаг ON, 2.0 вставлена, но не текущая | /author-terms — 1.2. Бизнес: экран статуса «Нужно принять соглашение», формы нет. `submit_v3`, `moderator_business_track_review` → `business_unified_agreement_inactive`; `business_catalog_sync` → `not_ready` (`unified_agreement_inactive`); opt-in ещё доступен |
| 3 | Переключить текущую (grace) | /author-terms — 2.0 и ссылка «Редакция 1.2». У автора на 1.2 баннер «Вышла редакция 2.0», продажи и выплаты работают |
| 4 | Сергей в своём кабинете: «Юридические документы» | Одна галочка, не отмечена. Текст «…редакция 2.0… АудиоЛад Бизнес… сублицензирование». После принятия — «Принято» |
| 5 | Тот же шаг в режиме сопровождения | Галочки нет, предупреждение «только сам автор». POST → 403 |
| 6 | Бизнес у Сергея после принятия | Шаг 1 «Принято», форма проверки прав **без галочек**. Отправка по одному треку **Aurafon** (Suno, ссылка + 2 файла) → «На проверке» |
| 6а | Проверка прав по треку из альбома, где есть неопубликованный трек | Отправка проходит (проверяется только выбранный трек) |
| 7 | Модератор (другой админ) одобряет проверку | Шаг 2 «Подтверждено». **Сразу**, без ручного шага, опубликованные треки Aurafon и Jazz Relax получают гранты (оба слоя) и показываются «В АудиоЛад Бизнес» |
| 7а | Форма принятия открыта под 1.2, затем выполнено переключение на 2.0, автор нажимает «Принять» в старой вкладке | `409 terms_version_changed`, сообщение «Редакция документа изменилась…»; акцепт не записан |
| 8 | `business_catalog_sync(<Сергей>)` dry-run | После автопоступления `ready` пуст; треки с грантами — `already_granted`, с чужим действующим грантом — `other_rightsholder_grant`, с отозванным или истёкшим грантом — `historical_rights_restriction` |
| 9 | `business_catalog_sync(<Сергей>, false)` | Ничего не создаёт (идемпотентно). Гранты только `platform_agreement`, RU. Старые 24 гранта (`source_type = 'other'`) не изменены. «В АудиоЛад Бизнес» — только при обоих действующих слоях |
| 9а | Опубликовать новый трек в продукте Aurafon | Гранты появляются автоматически при публикации |
| 10 | Модератор блокирует один трек Jazz Relax | Трек «Не допущен — права отозваны или оспорены», его гранты соглашения отозваны, остальные треки на месте. Повторная синхронизация или новая публикация его не возвращают; вернуть может только решение «допустить». Плеер точки его не воспроизводит, даже если у трека есть старые гранты (`resolve_business_track_eligibility` → `INELIGIBLE`) |
| 11 | Модератор запрашивает доказательства по треку Aurafon | Трек «Нужны доказательства по этому треку». Подтверждение одного трека не распространяется на другие |
| 12 | Автор на 1.2 (тестовый) открывает Бизнес | Баннер плюс шаг 1 «Нужно лично принять». `submit_v3` из консоли → `business_unified_agreement_required` |
| 13 | /business-documents/music-rights-declaration | Баннер «Документ в архиве», текст прежний (хэш тот же) |
| 13а | /business-documents/program-terms и business.audiolad.ru/documents/b2b-terms | Флаг ON: п. 1 ссылается на «Единое коммерческое соглашение с правообладателем» (2.0, разделы 7 и 8). Флаг OFF: прежняя r6 со ссылкой на «Заявление правообладателя», байт в байт |
| 14 | Прямой вызов `author_business_product_optin` с JWT автора | `permission denied` |
| 15 | Откат: 03-rollback-switch, флаг OFF | Снова 1.2 и старая форма. Акцепты 2.0 в журнале сохранились |
