# Гостевые оценки – включение и откат

Код задачи f8f5908b. Пока флаги выключены, зарегистрированные оценки работают как раньше.
Миграция аддитивная: `supabase/migrations/20270113120000_guest_practice_ratings.sql`.
Этот документ не включает флаги и не применяет миграцию.

## Переменные окружения

Обязательные имена, значения не коммитить:

- `GUEST_RATINGS_SESSION_SECRET` – стабильный случайный секрет подписи cookie `al_guest`.
- `RATINGS_UI_ENABLED` – уже существующий флаг звёзд. Без него UI оценок скрыт.
- `RATINGS_SIGNAL_HMAC_SECRET` – уже существующий секрет HMAC сети и устройства. Сырой IP не пишется.

Сбор и показ, все по умолчанию выключены (`1` / `true` / `yes` / `on`):

- `GUEST_RATINGS_COLLECT_ENABLED` – писать гостевые голоса, публичное среднее не менять.
- `GUEST_RATINGS_PUBLIC_ENABLED` – показать отдельно «Оценки гостей». В среднее не мешает.
- `GUEST_RATINGS_INCLUDE_IN_AGGREGATE` – добавить неисключённые и несвязанные гостевые звёзды в публичное среднее. Отдельное решение Сергея.

CAPTCHA, пустые ключи допустимы, пока сбор выключен. Если проверка нужна, а ключа нет, гостевой голос не записывается. Зарегистрированный путь от провайдера не зависит.

- `GUEST_RATINGS_CAPTCHA_PROVIDER` – `smartcaptcha` (по умолчанию) или `turnstile`.
- `NEXT_PUBLIC_YANDEX_SMARTCAPTCHA_CLIENT_KEY`
- `YANDEX_SMARTCAPTCHA_SERVER_KEY`
- `NEXT_PUBLIC_TURNSTILE_SITE_KEY`
- `TURNSTILE_SECRET_KEY`

`GUEST_RATINGS_TEST_MODE` только на стенде. На публичном сайте его быть не должно. В этом режиме без секрета сессии используется тестовый секрет, а токены `test:pass`, `test:fail` и `test:outage` не ходят к провайдеру. Интерфейс сам эти токены не отправляет.

## Порядок включения

1. Разобрать черновик PR. Не сливать и не выкатывать, пока Сергей не подтвердит.
2. На стенде применить только `20270113120000_guest_practice_ratings.sql`. Флаги гостевых оценок не ставить. Проверить, что зарегистрированные оценки читаются и правятся как раньше.
3. Задать `GUEST_RATINGS_SESSION_SECRET`. Ключи CAPTCHA пока пустые, флаги выключены.
4. Включить `GUEST_RATINGS_COLLECT_ENABLED` на стенде вместе с `RATINGS_UI_ENABLED`. Голос появляется в `guest_practice_ratings` после серверного прослушивания. Публичное среднее не меняется. В админке «Оценки → Слушатели → Гости» виден только `Гость · ID сессии {uuid}`. Повторная оценка обновляет одну строку и пишет событие. Одинаковая оценка событие не создаёт. Регистрация с той же cookie переносит голос один раз; если у аккаунта голос уже есть, побеждает он, гостевая строка помечается superseded и не удаляется.
5. Задать ключи SmartCaptcha. Первый прогретый голос проходит без проверки. Подозрение запрашивает невидимую проверку, визуальное задание – только после неудачи или быстрой серии. Плохой токен и недоступность провайдера не пишут гостевой голос. Зарегистрированная оценка при этом сохраняется. Горячая сеть (много разных guest id на одном HMAC) включает только невидимую проверку и никого не блокирует.
6. По желанию включить `GUEST_RATINGS_PUBLIC_ENABLED`, чтобы показать отдельные итоги гостей.
7. `GUEST_RATINGS_INCLUDE_IN_AGGREGATE` включать только отдельным решением Сергея, после просмотра раздельных итогов. Музыка и аудиопрактики остаются в своих средних.

## Откат

Снять `GUEST_RATINGS_COLLECT_ENABLED`, `GUEST_RATINGS_PUBLIC_ENABLED` и `GUEST_RATINGS_INCLUDE_IN_AGGREGATE`. Поведение возвращается сразу: гостевой UI и запись закрыты, публичное среднее снова только из `practice_ratings`. Таблицы оставить. Удаление строк и `DROP` – отдельное решение, в этот откат не входит. Nginx, forwarded-IP и перезапуск production этим изменением не трогаются.
