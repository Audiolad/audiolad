# Гостевые оценки – включение и откат

Код задачи f8f5908b. Пока флаги выключены, зарегистрированные оценки работают как раньше.
Миграция аддитивная: `supabase/migrations/20270113120000_guest_practice_ratings.sql`.
Этот документ не включает флаги и не применяет миграцию.

## Переменные окружения

Обязательные имена, значения не коммитить:

- `GUEST_RATINGS_SESSION_SECRET` – стабильный случайный секрет подписи cookie `al_guest`.
- `RATINGS_UI_ENABLED` – уже существующий флаг звёзд. Без него UI оценок скрыт.
- `RATINGS_SIGNAL_HMAC_SECRET` – уже существующий секрет HMAC сети и устройства. Сырой IP не пишется.

Сбор и показ, все по умолчанию выключены (`1` / `true` / `yes` / `on`):

- `GUEST_RATINGS_COLLECT_ENABLED` – писать гостевые голоса, публичное среднее не менять. На production без `GUEST_RATINGS_SESSION_SECRET` сбор остаётся выключенным.
- `GUEST_RATINGS_PUBLIC_ENABLED` – показать отдельно «Оценки гостей». В среднее не мешает.
- `GUEST_RATINGS_INCLUDE_IN_AGGREGATE` – добавить неисключённые и несвязанные гостевые звёзды в публичное среднее. Отдельное решение Сергея.
- `GUEST_RATINGS_CLAIM_COPY_ENABLED` – при регистрации скопировать гостевые звёзды в `practice_ratings`. Отдельное решение Сергея, по умолчанию выключено. Без этого флага вход только связывает гостевую строку с аккаунтом и публичное среднее не меняет. Пока выключен сбор, вход не вызывает claim и cookie не стирает.

CAPTCHA, пустые ключи допустимы, пока сбор выключен. Если проверка нужна, а ключа нет, гостевой голос не записывается. Зарегистрированный путь от провайдера не зависит.

- `GUEST_RATINGS_CAPTCHA_PROVIDER` – `smartcaptcha` (по умолчанию) или `turnstile`.
- `NEXT_PUBLIC_YANDEX_SMARTCAPTCHA_CLIENT_KEY`
- `YANDEX_SMARTCAPTCHA_SERVER_KEY`
- `NEXT_PUBLIC_TURNSTILE_SITE_KEY`
- `TURNSTILE_SECRET_KEY`

`GUEST_RATINGS_TEST_MODE` только на стенде. При `NODE_ENV=production` режим принудительно выключен: тестовый секрет и токены `test:pass`, `test:fail`, `test:outage` не принимаются. Если секрет сессии не задан, сбор на production не включается. Вне production и только при явном тестовом режиме без секрета сессии используется тестовый секрет, а тестовые токены не ходят к провайдеру. Интерфейс сам эти токены не отправляет.

## Порядок включения

1. Разобрать черновик PR. Не сливать и не выкатывать, пока Сергей не подтвердит.
2. На стенде применить только `20270113120000_guest_practice_ratings.sql`. Флаги гостевых оценок не ставить. Проверить, что зарегистрированные оценки читаются и правятся как раньше.
3. Задать `GUEST_RATINGS_SESSION_SECRET`. Ключи CAPTCHA пока пустые, флаги выключены.
4. Включить `GUEST_RATINGS_COLLECT_ENABLED` на стенде вместе с `RATINGS_UI_ENABLED` и уже заданным `GUEST_RATINGS_SESSION_SECRET`. Голос появляется в `guest_practice_ratings` после серверного прослушивания. Публичное среднее не меняется. В админке «Оценки → Слушатели → Гости» виден только `Гость · ID сессии {uuid}`. Повторная оценка обновляет одну строку и пишет событие. Одинаковая оценка событие не создаёт. Вход с той же cookie только связывает гостевую строку с аккаунтом. Если у аккаунта голос уже есть, побеждает он, гостевая строка помечается superseded и не удаляется. Копирование звёзд в `practice_ratings` этим шагом не делается.
5. Задать ключи SmartCaptcha. Первый прогретый голос проходит без проверки. Подозрение запрашивает невидимую проверку, визуальное задание – только после неудачи или быстрой серии. Плохой токен и недоступность провайдера не пишут гостевой голос. Зарегистрированная оценка при этом сохраняется. Горячая сеть (много разных guest id на одном HMAC) включает только невидимую проверку и никого не блокирует.
6. По желанию включить `GUEST_RATINGS_PUBLIC_ENABLED`, чтобы показать отдельные итоги гостей.
7. `GUEST_RATINGS_INCLUDE_IN_AGGREGATE` включать только отдельным решением Сергея, после просмотра раздельных итогов. Музыка и аудиопрактики остаются в своих средних.
8. `GUEST_RATINGS_CLAIM_COPY_ENABLED` включать только отдельным решением Сергея. Тогда новая регистрация без своего голоса один раз копирует гостевые звёзды в `practice_ratings`. Уже связанная строка повторно не копируется. Пока флаг выключен, вход публичное среднее не меняет.

## Откат

Снять `GUEST_RATINGS_COLLECT_ENABLED`, `GUEST_RATINGS_PUBLIC_ENABLED`, `GUEST_RATINGS_INCLUDE_IN_AGGREGATE` и `GUEST_RATINGS_CLAIM_COPY_ENABLED`. Поведение возвращается сразу: гостевой UI и запись закрыты, вход не вызывает claim, публичное среднее снова только из `practice_ratings`. Уже скопированные при включённом флаге строки в `practice_ratings` этим снятием не откатываются: их правка – отдельное решение. Таблицы оставить. Удаление строк и `DROP` в этот откат не входят. Nginx, forwarded-IP и перезапуск production этим изменением не трогаются.
