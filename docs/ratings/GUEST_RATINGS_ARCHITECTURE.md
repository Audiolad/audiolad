# Гостевые оценки и защита от ботов — архитектурная записка (проект, задача 612f9c76)

Статус: **ПРОЕКТ для выбора Сергея. Ничего не реализовано и не включено.** Мутация production
(миграции, новые таблицы, auth flow) и публичное включение — только по отдельному согласованию.
PR #891 этим документом **не расширяется**: он остаётся read-only аналитикой зарегистрированных.

Основание — решение Сергея от 17.10.2026 (Company Core, уточнение 53ff0c99): гости без
регистрации могут ставить 1–5★ платным и бесплатным аудио после **реального** достаточного
прослушивания, включая бесплатное превью платного продукта. Нужна лёгкая защита от ботов с
минимальным трением.

## 1. Ограничения, которые нельзя нарушать

* В `practice_ratings` не пишется фиктивный `user_id`. «Фейковые зарегистрированные»
  `auth.users` не создаются.
* CAPTCHA подтверждает вероятное участие человека, но **не** является постоянной
  идентичностью. Cookie = браузер, а не человек. Ограничение честно указывается: при очистке
  cookie или смене устройства человек может проголосовать снова.
* Текущие голоса не удаляются. Правила для зарегистрированных не ухудшаются: авторы оценивают
  свои продукты, оценки после `catalog_preview` сохраняются.
* Нет блокировок по одному IP или CGNAT. И главное: **сейчас доверенный IP на проде не
  работает** (аудит, п. 2.1). Исправление nginx — обязательное предусловие любых IP-лимитов.

## 2. Общая основа всех вариантов

* **Гостевая идентичность**: подписанная (HMAC) httpOnly `Secure` `SameSite=Lax` cookie
  `al_guest` со случайным `guest_id` (UUID), создаётся сервером. Клиентский localStorage
  источником истины не является. В БД хранится только `guest_id`, без ПДн.
* **Серверная eligibility**: тот же механизм, что у `practice_listen_stats` — серверная разница
  позиций, тик ≤15 с, разрыв >20 с даёт +0, потолок по реальному времени. Порог ≥30 с или
  обоснованный порог по длине доступного фрагмента. Отдельная таблица
  `guest_listen_stats(guest_id, practice_id, real_listened_ms, rating_eligible_at)`.
* **Голос**: таблица `guest_practice_ratings(guest_id, practice_id, stars, created_at,
  updated_at, verification, ip_hmac, excluded_at, …)` с `UNIQUE(guest_id, practice_id)`:
  один текущий голос, правка — это UPDATE плюс событие в `guest_practice_rating_events`.
* **Ограничения**: rate-limit на `guest_id` и на (доверенный IP, /24 или /48) **мягкий**.
  Превышение не означает отказ: включается повторная проверка CAPTCHA. Потолок новых
  guest_id на IP в сутки — с учётом CGNAT, только как триггер проверки.
* **Публичный агрегат**: `зарегистрированные + верифицированные гости`. Включается за
  флагом. На этапе аудита итоги registered и guest считаются и показываются раздельно.
* **Регистрация после гостевой оценки**: при входе гостевые голоса привязываются к аккаунту
  (`claimed_by_user_id`). Если у пользователя уже есть голос за тот же продукт, действует
  голос аккаунта, а гостевой помечается `superseded` и в агрегат не входит. Двойного голоса не
  бывает, история не смешивается молча.
* **Админка «Оценки → Слушатели»**: строка «Гость · ID сессии …», без ФИО и email; даты,
  оценённые продукты, нейтральные сигналы. Отдельные итоги registered и guest, метрики
  доверия и ошибок.

## 3. Варианты

| Вариант | Как работает | Трение | Защита | Объём |
|---|---|---|---|---|
| **A. Невидимая CAPTCHA на каждый гостевой голос** | SmartCaptcha invisible: `execute()` при нажатии звезды, сервер валидирует токен (одноразовый, TTL ≤10 мин) до записи | почти нулевое; челлендж (слайдер) видят только подозрительные | хорошая против простых ботов | средний |
| **B. Адаптивно (рекомендуется)** | первый голос гостя проходит без CAPTCHA, если guest_id «прогрет» (реальное серверное прослушивание ≥30 с, возраст cookie, нет всплеска с IP). CAPTCHA (invisible → слайдер) — при подозрении: много голосов за короткое время, новый guest_id с «горячего» IP, быстрые серии | минимальное | хорошая; CAPTCHA-затраты ниже | средний+ (нужны правила подозрительности и мониторинг ложных срабатываний) |
| **C. Гостевые голоса отдельно** | как A или B, но гостевой рейтинг виден отдельно («оценки гостей») и в основной агрегат не входит до накопления статистики | минимальное | максимальная прозрачность | малый+ |

Рекомендация: **B**, с этапом C на старте — сначала собирать гостевые голоса раздельно, затем
по данным решить, включать ли их в общий агрегат.

## 4. CAPTCHA: кандидаты

| | Яндекс SmartCaptcha (первый кандидат) | Cloudflare Turnstile Managed (альтернатива) |
|---|---|---|
| Режимы | обычный, **invisible** (челлендж только подозрительным), визуальные задания-слайдеры | managed / non-interactive / invisible |
| Стоимость | по документации Yandex Cloud: первые 10 000 корректных `/validate` в месяц бесплатно, далее около 110 ₽ за 1 000 (выше 100 000 дешевле). Платятся только корректные запросы | бесплатный тариф (условия проверить перед выбором) |
| Доступность в РФ | российский провайдер; нужна проверка в VK/MAX Mini App и iOS PWA | риски доступности в РФ — проверить на реальных сетях |
| Персональные данные | обязательно уведомить пользователя об обработке данных сервисом (баннер или текст) | аналогично |
| Сервер | `POST /validate` с серверным ключом, токен одноразовый | `siteverify`, токен одноразовый |

**Отказ провайдера**: fail-safe. Если CAPTCHA недоступна, гостевой голос не принимается,
показывается «Не удалось проверить, попробуйте позже», а голоса зарегистрированных работают как
раньше. Свою «рисованную» капчу не делаем.

## 5. Защита регистрации (одобрено как отдельный тестируемый проект)

После исправления доверенного IP в nginx:
* серверные лимиты регистраций по IP и другим надёжным признакам, с учётом shared IP и CGNAT;
* email-подтверждение или иной verified gate **до выставления рейтинга** зарегистрированным;
  сейчас `GOTRUE_MAILER_AUTOCONFIRM=true`, это изменение auth flow требует отдельного approval
  до релиза;
* антибот-вызов (SmartCaptcha или Turnstile) только при подозрительной активности, без CAPTCHA
  на каждый вход;
* лимит rating events и мониторинг ложных отказов;
* без блокировки 38 аккаунтов по непроверенному IP.

## 6. Влияние на ранжирование

Считается отдельно для «Музыки и звуков» и «Аудиопрактик и медитаций»: доля гостевых голосов
по сегменту, сдвиг средней и порядка при включении гостевых голосов (имитация, как S4). Перед
публичным включением — стресс-сценарий «десятки голосов одного человека из разных браузеров».

## 7. Оценка объёма и этапы

1. nginx: доверенный IP (отдельное OK, ~0,5 дня с проверкой).
2. Миграции `guest_*` (additive), cookie-сессия, серверная eligibility для гостей, запись
   голоса, CAPTCHA-валидация, тесты (~3–5 дней).
3. Админка: гости в «Слушателях», итоги registered и guest.
4. Флаг `guest_ratings_collect` (сбор без влияния на агрегат) → анализ → флаг
   `guest_ratings_public`. Каждый шаг включается отдельным решением Сергея.

Тесты: один guest × один продукт = один голос; правка без дубля; гость → регистрация без
двойного голоса; отказ CAPTCHA; недоступность провайдера; лимиты при общем IP; подделка
heartbeat и перезагрузки не дают eligibility.
