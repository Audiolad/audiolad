# Деплой сортировки каталога (популярность / рейтинг)

## 1. Миграция БД

1. Применить `supabase/migrations/20271126120000_catalog_listing_qualified_listen_counts.sql` на production **до** или **вместе с** выкладкой кода, который вызывает RPC `catalog_practice_qualified_listen_counts`.
2. Убедиться, что `playback_usage_settings.listening_time_valid_from` уже задан миграцией `20261127120000_playback_usage_facts.sql` (в каждом окружении — своё значение `now()` на момент применения).
3. Без RPC сортировка «Популярные» деградирует: метрики останутся нулевыми, ошибка логируется как `catalog_listing_sort_metrics_error`.

## 2. Приложение

1. Собрать и выкатить Next.js после успешного CI (`PR Repository Validation`).
2. Перезапуск PM2 `audiolad` — по согласованной runbook, не автоматически из агента.
3. Проверить вручную: `/catalog`, `/catalog?sort=popular`, `/catalog?sort=rating`, пагинация, MAX каталог (сортировка в теле POST).

## 3. Откат

| Слой | Действие |
|------|----------|
| Код | Откатить деплой на предыдущий коммит; сортировки `popular`/`rating` станут недоступны, URL с `sort=popular` парсятся, но метрики не грузятся. |
| RPC | `DROP FUNCTION catalog_practice_qualified_listen_counts` — только если откатываем фичу целиком; на факты `playback_usage_facts` не влияет. |
| Данные | Не требуется; миграция только добавляет функцию. |

## 4. Методика и граница учёта

См. [CATALOG_SORT_METHODOLOGY.md](./CATALOG_SORT_METHODOLOGY.md) — порог 60 с, `session_id` для альбома.

**Авторитетная граница популярности:** `playback_usage_settings.listening_time_valid_from` — `now()` при применении `20261127120000_playback_usage_facts.sql` в **данном** окружении (на проде это дата деплоя metering, не константа в коде).

**Аудит прод-фактов (справочно):** по `docs/ratings/CATALOG_RATING_SORT_FILTER_SPEC.md` / `RATINGS_AUDIT_2026-10-17.md` первые строки `playback_usage_facts` с ненулевым `listened_ms` на audiolad.ru — не ранее **2026-09-26**; эта дата **не подменяет** `listening_time_valid_from` и может быть раньше порога metering (старые сэмплы без гарантии полноты `listening_key`).

## 5. Smoke после деплоя

1. `/catalog` — чипы **Новые | Популярные | По рейтингу**, по умолчанию Новые.
2. `/catalog?sort=popular` — сетка меняется, `?sort=popular` в URL; вторая страница пагинации без 500.
3. `/catalog?sort=rating` — аналогично.
4. Админ → аналитика каталога → блок **«Методика расчёта популярности и рейтинга»** раскрывается, дата metering и эталон 2026-09-26 упомянуты.

## 6. Визуальный чеклист владельца (audiolad.ru, после deploy)

Без staging-доступа агент не делает скриншоты; выполнить вручную:

| # | Где | Что проверить |
|---|-----|----------------|
| 1 | [Каталог](https://audiolad.ru/catalog) | Три кнопки сортировки над сеткой; активная подсвечена; порядок карточек меняется при переключении. |
| 2 | Популярные | Продукт с известными длинными прослушиваниями выше нулевых; нет пустой сетки. |
| 3 | По рейтингу | Продукт с большей суммой звёзд выше; при равенстве — новее публикация. |
| 4 | Пагинация | «Вперёд» на popular/rating сохраняет `sort` в URL. |
| 5 | Админ | Методика совпадает с `CATALOG_SORT_METHODOLOGY.md` (60 с, session_id, даты). |
