# Райтер – статья по брифу до чернового PR

«Райтер» – автор статей АудиоЛада на Cloud.ru Foundation Models. Пайплайн получает бриф, генерирует статью сразу в формате сайта, проверяет её детерминированными валидаторами и открывает **черновой** PR. Мерж и деплой остаются за независимым ревьюером и обычной политикой деплоя: пайплайн никогда не мержит и не деплоит.

## Запуск

```bash
npx tsx scripts/writer/run.mjs --brief path/to/brief.json
# или
npm run writer -- --brief path/to/brief.json
```

Параметры:

| Флаг | Назначение |
|---|---|
| `--model` | по умолчанию `openai/gpt-oss-120b`, для `--site sz` – `openai/gpt-5.5` (победитель сравнения моделей на пакете 07). Доступны все модели из `TARIFF` в `lib/cost.mjs` |
| `--dry-run` | всё, кроме push и PR: коммит остаётся в локальном worktree |
| `--repair-model <id>` | только sz: модель repair из `SUPPORTED_MODELS`; по умолчанию модель прогона |
| `--repair-max-tokens N` | только sz: целое 1–32000; по умолчанию значение `--max-tokens` |
| `--repair-mode full\|targeted\|tiered` | только sz: `full` по умолчанию; `targeted` – patch выбранных полей; `tiered` – детерминированные правки, затем дешёвые фрагменты, GPT-5.5 только последним |
| `--tier-cheap-model` / `--tier-strong-model` | только с `tiered`: по умолчанию `openai/gpt-5.4-mini` и `openai/gpt-5.5` |
| `--tier-cheap-tries` | только с `tiered`: попытки дешёвой модели на один фрагмент (1–4, по умолчанию 2), затем одна попытка сильной |
| `--tier-cheap-max-tokens` / `--tier-strong-max-tokens` | только с `tiered`: нижняя граница дешёвого яруса 800. Для `gpt-oss-120b` и `Qwen3.6` потолок выше (2400, для длинного фрагмента 4000); обрыв JSON повторяется один раз с удвоенным потолком, если он влезает в бюджет яруса. Сильный потолок 800: 1200 токенов выхода `gpt-5.5` уже дороже 6 ₽ |
| `--tier-cheap-budget` / `--tier-strong-budget` | только с `tiered`: сумма худших случаев яруса, 8 ₽ и 6 ₽ на статью. На пакет потолок умножается на число статей. FAQ пакета входит в ту же сумму. Внутри `--max-rub` |
| `--no-repair` | без автоматического раунда исправлений |
| `--offline` | без живой проверки ссылок на audiolad.ru |
| `--article file.json` | взять готовый JSON статьи вместо генерации (0 ₽) |
| `--max-rub 3` | лимит расходов Cloud.ru на прогон; вызов не стартует, если худший случай превысит лимит; только число > 0 и ≤ 800 (пусто, NaN, «3р» – отказ, код 1) |
| `--max-tokens 16000` | лимит ответа модели (модели рассуждающие, нужен запас); только целое 1–32000, иначе отказ |
| `--out dir` | каталог прогона (по умолчанию `~/.cache/writer/runs/<id>`) |
| `--keep-worktree` | не удалять worktree после прогона |

Проверить пайплайн без затрат: `npx tsx scripts/writer/run.mjs --brief scripts/writer/fixtures/brief.json --article scripts/writer/fixtures/article.json --dry-run --offline`.

Если после реального вызова связь с московским сервером оборвалась и `meta.json` с usage не получен, в бюджет засчитывается худший случай (промпт + `max_tokens` × тариф ответа), в отчёте помечено «худший случай: нет usage».

Коды выхода: 0 – успех, 1 – ошибка запуска, 2 – статья не прошла валидацию, 3 – проверки репозитория, 4 – найден секрет, 5 – превышен бюджет. При ненулевом коде PR не создаётся, причины – в `report.md` каталога прогона.

## Что происходит

1. **Бриф** проверяется (`lib/brief.mjs`). Тип статьи – только `practice` (по AGENTS.md: `ARTICLE TYPE: practice`).
2. Создаётся чистый worktree от свежего `origin/main`; из него читаются реестр статей, операционный мастер и поддержка блоков (таблица разрешена, только если в `types.ts` есть `kind: "table"`).
3. **Генерация – только на московском сервере.** На сервер уходят лишь `request.json` и `remote/generate.py`; ключ Cloud.ru читается внутри процесса из `/etc/audiolad/cloudru-fm.env` (root, 600) и никуда не выводится. Обратно возвращаются только JSON статьи и `meta.json` (токены, стоимость, статус). Учётные данные GitHub на сервер не попадают (без проброса агента и окружения). Ответ запрашивается по строгой JSON-схеме; если API отвергает `response_format`, выполняется один бесплатный повтор без схемы.
4. **Нормализация** (фиксируется в отчёте): U+2011 → дефис, длинное тире → «–», числовые диапазоны «30-60» → «30–60», пробелы между текстом и ссылкой в rich_paragraph, AudioLad → АудиоЛад, суффикс metaTitle « – АудиоЛад», заголовки «Смотрите также» = H1 целевых статей.
5. **Валидаторы** (`lib/validate.mjs`): обязательные поля и длины, разделы/FAQ/таблица, объём; цитаты в «ёлочках», "прямых", „немецких“ и “английских” кавычках дословно по материалам брифа, обязательные цитаты; внутренние ссылки – статьи из реестра и разрешённые брифом, практики из брифа, живой ответ 200; ссылки на другие сайты запрещены (правило владельца от 23.10): кроме audiolad.ru допускается только sergey-zoya.ru и только адреса из брифа, источники называются текстом без ссылки; адреса в тексте – тоже ошибка: `example.com/page`, `t.me/x`, `//host/x`, `www.…`, домены .рф, `mailto:`/`tel:`/`tg:` и e-mail (упоминания audiolad.ru и sergey-zoya.ru допустимы); нет длинного тире, HTML и Markdown; нет обещаний исцеления, защиты, гарантий, исполнения желаний (исключения – только прямое отрицание глагола обещания: «не гарантирует», «без гарантий», «нельзя гарантировать», вопрос «гарантирует ли…», а также дословные цитаты; другое «не» рядом не спасает); нет настройки на дискомфорт (правило владельца от 23.10): «дискомфорт», «неприятные ощущения», «остановите/прекратите запись (прослушивание, практику)», «запись следует остановить», «если станет плохо» – ошибка, практика описывается только через хорошее; ключи в title, metaTitle, metaDescription и тексте; нет дублей slug, главного ключа, заголовков; нет упоминания «таблица ниже» без блока table.
6. Если черновик короче минимума, один вызов **expand** просит только новые абзацы по разделам (без ссылок и цитат); они добавляются детерминированно и проверяются заново. Затем при ошибках – **один раунд исправлений** Райтером со списком ошибок, затем повторная проверка. Не прошло – PR не создаётся.
7. **Конвертация** (`lib/convert.mjs`): модуль `src/lib/seo/articles/content/<slug>.ts`, импорт и запись в `registry.ts`, запись PLANNED в `SEO_OPERATIONAL_MASTER.json` и `VERIFIED_AUDIT.json`, счётчики статей в тестах N → N+1.
8. **Проверки**: `tsc --noEmit` (4 ГБ памяти), eslint изменённых файлов, SEO-тесты. Тест, который падает и на чистом main, отмечается как «не регрессия» и не блокирует.
9. **Публикация** (`lib/publish.mjs`): коммит в ветку `writer/<slug>`, gitleaks и шаблонный поиск секретов, push (без force), черновой PR с меткой «Райтер (Cloud.ru <модель>)», стоимостью и результатами валидаторов в описании.

Расходы каждого вызова пишутся в `~/.cache/writer/ledger.jsonl`. Тарифы (₽ с НДС за 1 млн токенов): gpt-oss-120b – 15,86 вход / 61 выход; Qwen3.6-35B-A3B – 219,60 / 329,40. Массовая генерация – только с отдельным согласованием.

JSON-файл, пример – `examples/pilot-brief.json`. Поля:

| `slug` | да | латиница через дефис, не должен существовать |

| `secondaryKeywords` | нет | дополнительные ключи |

| `relatedPractices` | нет | до 3 практик того же формата |
| `internalLinks` | нет | `[{href, note}]` – разрешённые внутренние ссылки (`/articles/<slug>` и др.) |
| `minInternalArticleLinks` | нет | минимум ссылок на статьи в тексте (2) |

| `externalLinks` | нет | разрешённые внешние URL – только `https://sergey-zoya.ru/…` (другие сайты – ошибка брифа); `url` источников виден только ревьюеру и в статью не попадает |
| `forbiddenPhrases` | нет | дополнительные запрещённые слова |
| `wordCount`, `sections`, `faq`, `seeAlso` | нет | диапазоны `{min, max}` |
| `table` | нет | `{mode: required/optional/forbidden, columns, rows, note}` |
| `extraInstructions` | нет | дополнительные редакционные требования: строка или массив строк |
| `publishedAt` | нет | дата `YYYY-MM-DD` (по умолчанию сегодня, МСК) |
| `pilot` | нет | `true` – пометка «пилот» в PR |

## Режим sz: статьи sergey-zoya.ru

`--site sz` пишет пакет из 1–5 статей для sergey-zoya.ru и открывает **один черновой PR** в `Audiolad/sergey-zoya-site` (ветка `writer/sz-<pack>`). Модель пишет только поля (схема `sergey_zoya_article`), а постоянные блоки (frontmatter, карусель ангелов, MAX, плеер практики, карточки экспертов, дисклеймер, «Читайте также») вставляет сборщик по канону пакета 03 и статьи angel-hranitel. Все знания о сайте лежат в `lib/sites/sz/`, а человекочитаемая сводка – в `lib/sites/sz/knowledge/GUIDE.md`.

Каждая статья пакета даёт в PR:

- `content/articles/<slug>.md`;
- OG `public/media/og/<slug>.jpg` (`make-og.py`, 1200×630);
- запись в `scripts/fixtures/story-openings.json`.

На весь пакет:

- счётчик `check-canonical-order` увеличивается на N;
- сгенерированный гейт `scripts/check-stageNN-articles.mjs` подключается в `npm test`;
- пишется SEO-отчёт `docs/seo-stage21/SEO-REPORT-<pack>.md`.

Затем выполняются локальные проверки сайта (шаги `npm test` по отдельности, по 10 минут на шаг, сравнение с чистым main: блокируют только регрессии) и `next build`. Их результаты идут в описание PR. Мерж и деплой не выполняются.

Коды выхода:

- 1 – запуск;
- 2 – бриф или статьи не прошли проверки, PR не создан;
- 3 – регрессия проверок сайта;
- 4 – секрет;
- 5 – бюджет.

### Пробный гибридный режим

Дефолты не меняются: sz использует `openai/gpt-5.5`, repair – ту же модель,
тот же `--max-tokens` и полный запрос (`full`). `DEFAULT_MODEL` для АудиоЛада
остаётся `openai/gpt-oss-120b`. Гибрид – пробный режим, требует независимой вычитки.
Пример отдельно согласованного запуска (эта задача меняет код, сам запуск не выполняется):

```bash
npx tsx scripts/writer/run.mjs --site sz --repo ../sergey-zoya-site --briefs pack.json \
  --model openai/gpt-5.4-mini --repair-model openai/gpt-5.5 \
  --repair-mode targeted --repair-max-tokens 4000 --max-rub 45
```

Тариф `openai/gpt-5.4-mini`: 147,315 ₽ вход / 883,89 ₽ выход за 1 млн токенов
с НДС (GET /v1/models Cloud.ru, 2026-10-24, `models-prices.tsv`). Неизвестная
модель и невалидные параметры repair отклоняются до любых трат, код 1.

`targeted` отправляет короткие правила, ошибки с требуемыми длинами и текущие
значения только выбранных полей верхнего уровня. Вложенная ошибка включает поле
целиком; `sections` сопоставляется разделам основной части, `table` –
`tableSection`. Для ошибок без точной привязки используются фрагменты текста
из сообщения гейта и сопоставление по коду; при неоднозначности включаются все
поля-кандидаты, вплоть до всех полей статьи. Факты и запреты берутся из брифа,
материалы практики – при правке её описания, цитаты/контекст/тексты источников –
при ошибках экспертов или цитат. Тексты источников, уже прочитанные при проверке
брифа, сохраняются для этого запроса. Полный system-промпт, LESSONS и образец
тона в targeted не отправляются.

Для `unique` и `unique-pack` поле берётся по тексту в «ёлочках», поэтому
дублирующийся `faqHeading` попадает в patch, даже если гейт записал поле
`sections`. Если в сообщении нет цитаты, а речь о заголовке, в кандидаты
добавляется и `faqHeading`. Ошибка длины основной части по-прежнему не трогает
`faqHeading`. `bold-query` ищется по жирному фрагменту (последние «ёлочки»);
если его нет в тексте, правятся `question` и `finalQuestion`.

При правке `story`, `transition` или `storyEnding` все три части передаются как
`storyContext` – только для чтения. Менять можно лишь выбранные поля; героев,
факты и детали нужно сохранить.

До merge patch нормализуется так же, как при сборке, и только потом проверяется.
Правило одно для любого поля: после снятия невидимых символов, жирного `**` и
служебного заголовка «Чем закончилась история.» в тексте должно остаться
достаточно слов (тезис – от 3, пояснение и окончание истории – от 8 слов и 2
предложений, заголовки – от 2, пункт чек-листа – от 2, обычная проза – от 4;
имя и ячейка таблицы могут быть короче). «Наденьте наушники.» проходит,
«а» / «б» и «главная мысль» – нет. Заглушка «главная мысль» и текст, который от неё почти не
отличается («главная мысль а»), не проходят. То же делает гейт на уже собранной
статье: однобуквенные тезис и пояснение, пустое окончание, пустой вводный абзац
и пустое финальное приглашение статью не пропускают. `experts` по-прежнему
обязан содержать ровно экспертов брифа в исходном порядке и без дублей.
Нарушение отклоняет весь patch: исходная статья сохраняется, причина пишется
в лог, warnings и `repairSkipped: rejected: …`.

Ответ – строгий JSON patch с подсхемами из `szArticleSchema`, без посторонних
полей. Проверяется и вложенная структура; валидный patch заменяет выбранные
поля целиком, остальные сохраняются. Невалидный, пустой или неполный patch
сохраняет исходник с предупреждением. Затем снова выполняются нормализация,
сборка и весь `checkSzArticle`. Число карточек не доказательство: сборщик всегда
строит их из брифа. Успешный ответ модели сам по себе не означает прохождение гейта.

Порядок размеров: на офлайн-эталоне angel-hranitel с ошибками `description`
полный repair содержит около 55 тыс. символов сообщений, targeted – около
1,1 тыс. (примерно в 50 раз меньше; оценка токенов для OpenAI около 25 тыс.
против 0,7 тыс.). Размер JSON-схемы сюда не включён; она также сокращается до
выбранных подсхем. При правке разделов ожидаются тысячи/десятки тысяч символов;
при неоднозначных ошибках или больших исходных текстах экспертов экономия
будет меньше. Это оценка размера запроса, а не измерение платного API-вызова.

`tiered` не заменяет `full`. Его включают явно: `--repair-mode tiered`. Сначала
детерминированные правки (омоглифы латиницы в кириллице, тире, обрезка слишком
длинных description/seoTitle/FAQ только по границе предложения, слияние лишнего
H2 и битый slug из списка брифа). Число в заголовке чек-листа и в заголовке шагов
сверяется со своим списком и поправляется без модели. Недостающую внутреннюю ссылку
вплетает дешёвый фрагмент: описательный анкор внутри предложения другого раздела,
не «Подробнее: [материал]» в конец абзаца. Общий анкор («материал», «здесь», «подробнее»)
меняется только в своём предложении; если он стоит в истории или в цитате, ссылка переносится в обычный абзац, а цитата и остальные предложения остаются дословными. Несколько склеек «Подробнее:» и «Читайте также:» снимаются все, без хвоста «Подробнее: .»; такой хвост, пустые []() и двоеточие перед закрывающей кавычкой гейт не пропускает. Раздел, который пересказывает историю, уходит в практические шаги,
а текст истории не меняется. Каждый дополнительный запрос брифа встречается в тексте
хотя бы раз. Ответ на открытый вопрос FAQ не начинается с «Да» или «Нет». Если целое предложение в лимит не помещается, поле не
режется и уходит дешёвой модели. Обрыв вроде «Это не» гейт не пропускает.
Затем дешёвая модель чинит один фрагмент за вызов (description, один ответ FAQ,
один короткий раздел, только абзац перехода, тезис, историю), без текста всей статьи.
Переход без точной формы запроса чинит дешёвый фрагмент одного абзаца: запрос
входит дословно, падеж согласован, суммарное число вхождений остаётся в диапазоне.
Короткая основная часть дописывается одним новым абзацем или концом одного шага,
без переписывания статьи; худший случай сильного вызова считается по токенам этого
фрагмента. Лишний точный запрос чинит только фрагмент одного абзаца основной части:
не заголовок, не description, не переход, не FAQ и не абзац с цитатой. Цитата – это
«…», "…", '…', ‘…’, ‹…›, незакрытая « или „, врезка `>` или `<blockquote>` в любом месте абзаца. Если
лишний запрос остался только внутри такой цитаты, фрагмент не строится. Модель переписывает
абзац без дословного запроса, число вхождений не опускается ниже 2, остальные абзацы
не меняются. Сильный ярус считает худший случай каждого починимого фрагмента отдельно и не снижает потолок токенов. Ошибка без фрагмента или ошибка, чей худший случай один больше бюджета, не отменяет сильные вызовы для остальных. Повтор обрыва по-прежнему оставляет место под худший случай других ещё открытых фрагментов. Дешёвый description получает текущую длину и цель 150 символов (допустимо 140–160); вариант вне диапазона не обрезается, а ближайший целиком переписывается короче или длиннее. Description не начинается с запроса в кавычках: «запрос» в начале становится «Запрос» без обрезки слова. Повторяющийся вопрос FAQ переписывается отдельно и снова сверяется с вопросами других статей; промпт знает тему, запрос и роль слота, а вопрос о специалисте остаётся вопросом о специалисте. Если такого вопроса нет, дешёвый фрагмент переписывает последний слот FAQ. Запрещённая фраза чинится отдельно в каждом месте, включая ячейку таблицы: отклонённый ответ с новой запрещённой фразой тратит попытку только этого места. Поздний точный или почти точный повтор абзаца удаляется без модели, ранний абзац и любые кавычки в нём не меняются, гейт сообщает каждый повтор. После промахов тот же
фрагмент один раз уходит в сильную модель. Ответ
сверяется с запретами брифа, дискомфортом, ссылками и правилами фрагмента до того, как он попадёт в статью.
Голый адрес без схемы (`example.com/candle`, `t.me/…`, чужой `www.…`, `сайт.рф`, `www.сайт.рф`, `пример.москва`, `xn--…`), почта и любой URL не с audiolad.ru
или sergey-zoya.ru отклоняются и фильтром ответа, и `checkSzArticle`. Один и тот же список допускает эти два
сайта, их `www` и поддомены. Чужой адрес внутри пути, query или якоря (`?next=https://evil.com`, `?u=evil.com`, `/path/evil.com`, `#evil.com`, `/сайт.рф`, `?u=сайт.рф`, `#сайт.рф`, `/path/evil%2Ecom` после одного-двух раскодирований %) тоже
отклоняется. «в конце.Далее» адресом не считается. `Node.js`, `Vue.js`, `Next.js`, `ASP.NET` и имена файлов вроде `photo.jpg` адресом не считаются. Внутренние `/s/` остаются. Источник можно назвать словами.
Если дешёвая модель оборвала JSON, тот же фрагмент один раз запрашивается с большим
потолком и это всё ещё одна попытка: в стоимость входят оба вызова. После `--tier-cheap-tries`
промахов тот же фрагмент один раз уходит в `--tier-strong-model` (по умолчанию
`openai/gpt-5.5`, до 800 токенов выхода). Если сильный вызов не влезает в бюджет
яруса, попытка считается использованной, а остальные дешёвые фрагменты всё равно
запрашиваются. После каждой правки снова выполняется весь `checkSzArticle`.
Статья готова только при пустом списке ошибок. Стоимость в отчёте – это generate
плюс все repair этой статьи; в «стоимость готовых» попадают только статьи,
прошедшие гейт. Офлайн-сравнение тарифов читает `scripts/writer/models-prices.tsv`
и не ходит в сеть. План контрольного платного прогона:
`scripts/writer/docs/TIERED_CONTROL_RUN.md`.

Бюджет общий: один `state.spentRub` на generate, expand (если предусмотрен
пайплайном) и repair. В sz отдельного expand нет. Каждый вызов проверяется по
собственной модели и `max_tokens`; лимит брифа дополнительно сужает `--max-rub`.
Если repair не помещается, журнал пишет «repair пропущен: бюджет», статья
получает `repairSkipped: "budget"`, сохраняется черновик и начинается следующая
статья. При нехватке бюджета generate останавливает прогон с кодом 5;
сохранённые черновики и отчёты остаются. Статьи с оставшимися ошибками блокируют PR.

В `report.json` и `report.md` каталога прогона указаны модель и стоимость каждого
вызова, итог, ошибки до/после repair и `repairSkipped` (`null`, если repair
выполнен; `"budget"`, если не влез в бюджет; `"rejected: …"`, если targeted
patch отклонён). В `ledger.jsonl` также записывается фактическая модель вызова.

### Как дать Райтеру пакет для sergey-zoya.ru

1. Склонируйте `Audiolad/sergey-zoya-site` и выполните там `npm ci`. Нужны `python3` с Pillow (для OG) и `gh` с правом на draft PR.
2. Посмотрите, кого из экспертов цитировали реже:

   `npx tsx scripts/writer/run.mjs --site sz --repo ../sergey-zoya-site --experts-report`

   Пул читается из всего `lib/sites/sz/knowledge/EXPERTS_RU.md` (40 экспертов, ячейки ЖРУ, МРУ, ЖЗАР, МЗАР). Другой файл подключается через `--experts path` или `WRITER_SZ_EXPERTS`.
3. Заполните бриф по шаблону `lib/sites/sz/knowledge/pack-brief.template.json` (пример – `fixtures/sz/pack-angel-replay.json`). На каждую статью нужны:
   - slug, запрос, H1, интент, завязка истории;
   - практика: название, длительность и путь `sergey-and-zoya/<slug>` на audiolad.ru, материалы со страницы практики дословно;
   - 2 эксперта из пула: вместе Ж, М, РУ и ЗАР; дословная цитата, источник текстом, `context`, `doesNotSay`, а также `sourceText` или `sourceFile` для сверки дословности;
   - ссылки: 2–8 статей `/s/<slug>` для текста и ровно 3 для «Читайте также». Можно ссылаться на статьи этого же пакета;
   - проверенные факты `facts`.
4. Бриф проверяется кодом до генерации:
   - в пакете не больше 5 статей;
   - slug, запросы и цитаты внутри пакета не повторяются;
   - один эксперт – не больше 2 раз на пакет;
   - `maxRub` (необязательно) – число рублей без кавычек и «₽», > 0 и ≤ 800; сужает `--max-rub`. Строка вроде «3 ₽», 0, отрицательное число – отказ до любых трат;
   - Барретт и Экман не ставятся в одну статью;
   - эксперты вне пула и недословные цитаты – ошибка.

   Если у эксперта ещё нет портрета на сайте, добавьте `card.photoFile`, или сначала слейте PR с портретами.
5. Проверка без затрат (готовые поля статей в `dir/<slug>.json`, без PR):

   `npx tsx scripts/writer/run.mjs --site sz --repo ../sergey-zoya-site --briefs pack.json --offline --fixtures dir --dry-run`
6. Реальный прогон:

   `npx tsx scripts/writer/run.mjs --site sz --repo ../sergey-zoya-site --briefs pack.json --max-rub 3`

   Генерация идёт только на московском сервере (ключ Cloud.ru не покидает `/etc/audiolad/cloudru-fm.env`), бюджет общий на пакет.

   Результат – черновой PR с отчётом: проверки Райтера по каждой статье, локальные проверки сайта, ротация экспертов, расходы. После него нужно вычитать статьи, проверить OG и портреты и отдать PR на ревью.

7. **После каждого независимого ревью** (и после ручных правок редактора) допишите его находки в `lib/sites/sz/knowledge/LESSONS.md`: раздел `## <дата> – <ревью со ссылкой>` и по пункту `- Неверно: «…» → Верно: «…». Почему: …` на каждую находку. Пишите обобщённо, чтобы урок подходил к другим темам. Весь файл уходит в каждый промпт, так Райтер учится на каждой правке. Если находку можно проверить кодом, добавьте правило в `rules.mjs` и негативный образец в `sz-unit.mjs`. `npm run test:writer` проверяет формат пунктов и то, что каждый урок попал в промпт. Главное правило в промпте: не уверена, что факт или традиция реальны, – не упоминай.

Что проверяет Райтер (`lib/sites/sz/rules.mjs`, те же правила в сгенерированном гейте):

- порядок блоков и frontmatter;
- автор «Зоя Петрова»;
- MAX только с `buttonLabel: "Выбрать ангела и получить послание в MAX"` и без `ctaUrl`;
- только «–»;
- нет исходящих ссылок (кроме практик audiolad.ru из брифа);
- нет обещаний, «призыва» и оберегов;
- нет предсказаний и настройки на дискомфорт (зеркало `check-no-discomfort-priming`);
- нет видимых дат и латиницы внутри русских слов;
- нет «Научные исследования показывают» без источника, служебных пометок источника в тексте («страница 16 сохранённого издания»), запроса в кавычках; дисклеймер ровно один;
- цитаты дословные, есть микс экспертов и выполнены ограничения «Осторожно» (Фредриксон без «3:1», Сигел – психиатр, Экман не о лжи, без «закона Зейгарник»);
- объёмы, FAQ и чек-лист;
- заголовки, FAQ и начала историй уникальны на сайте и в пакете.

## Тесты

`npm run test:writer` – офлайн-тесты валидаторов, нормализации и конвертера (`writer-unit.mjs`) и режима sz (`sz-unit.mjs`). В `sz-unit.mjs` эталонная статья angel-hranitel должна проходить без ошибок, а негативные образцы (дискомфорт, предсказание, внешние ссылки, max.ru, длинное тире, обещания, «призыв», чужой автор, другая кнопка MAX, видимая дата, латиница в слове, «3:1» Фредриксон) – давать ошибку. Ещё там проверяются бриф пакета, ротация и пул из 40 экспертов, сгенерированный гейт на синтетическом сайте и сравнение проверок сайта с базой.
